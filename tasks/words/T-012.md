# T-012 · Words in a real person's voice

Text for T-012a. Published 2026-09-27; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal.** The owner asked that every word inside the app reads like a real person wrote it, with no trace of AI wording ("at a glance, and many more"). A supervisor audit read all 449 user-facing strings (labels, buttons, errors, empty states, permission prompts, notifications, the 151 daily questions, the words later tasks prescribe) and kept 125 changes, each checked by two independent judges and a sweep. This task applies them and adds a test that stops the stock phrases from coming back. The voice rules themselves live in `docs/design/DESIGN.md` §8 "Voice"; `CLAUDE.md` rule 11 points there.

**Read first:** `CLAUDE.md` rules 11 and 12, `docs/design/DESIGN.md` §8.

## T-012a · Words in a real person's voice · needs T-009d

**Goal.** Every string in tables A to D below is in the app as written, the literals in table B come from `words`, and a test refuses the stock phrases and characters in every user-facing string.

**Do.**
1. Apply table A by key (the "Now" column is what the audit read; match by key, not by the old text). Where a key names an `app.json` mirror, change both; the existing test that pins `app.json` to `words` must stay green.
2. Table B: each literal a screen shows moves into `words` under a key you name in the screen's section (for example `words.today.cameraNotReady`, `words.today.photoFailed`, `words.cast.changeFailed`, `words.storylines.changeFailed`, `words.today.secondsLeft` as a function of `n`, `words.footage.storylinesEmpty`, `words.reminders.step` for the time buttons' spoken labels); the screen uses the key. The accessibility label in `FootageScreen.tsx:39` reads like the example in the table (kind, time, duration in words, the question or note, and "On this phone" when it applies).
3. Table C: replace each question's `text` by id. Ids, tags and slots stay; the bank keeps at least 140 templates and every per-tag count.
4. Table D: add these lines to `words` now, as `words.account` (the Settings Account section of T-010d) and `words.deletePage` (the public page of T-010c), with `{email}` and `{date}` as function arguments. T-010c and T-010d use them as they are.
5. `packages/story/src/words/voice.ts` (exported): `voiceBannedPhrases` (the list below) and `voiceBannedCharacters` (the list below). `bannedWords` stays exported as it is.
6. `packages/story/test/words.test.ts` gains, for every user-facing string: all string leaves of `words` (walk nested objects; skip `words.lab`, which is the developer design lab), every `words` function called with sample arguments (a date `2027-03-15`, numbers 1 and 7, the code `123456`, the email `sam@example.com`, a name `Sam`), every question template's text, and `recapWords` outputs for a sample week: none contains a phrase from `voiceBannedPhrases` (case-insensitive, whole words; a phrase with an apostrophe is matched literally), none contains a character from `voiceBannedCharacters`.

**Tests.** The new voice test above, failing before step 1 (the old strings contain "could not", "Try once more" and ";") and passing after; the existing words, question template, permission-string and screen tests pass.

**Allowed test changes.** A test that asserts the literal text of a string this task changes may switch to the new text or to its `words` key. No assertion is removed and no test is skipped.

**Acceptance.** Story and mobile typecheck, tests, lint, format, boundaries pass; the Design Lab recording still passes (it finds buttons by `words` keys); `rg -n "could not" packages/story/src/words apps/mobile/src --glob '!*.test.*'` finds nothing user-facing. UI visible: yes (every screen's words).
