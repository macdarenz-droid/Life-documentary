# T-010 · P4 Account (Better Auth on Workers and D1)

Text for T-010a–d. Published 2026-09-27; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P4.** A person can sign in (Sign in with Apple on iPhone, Google, or a six-digit code sent by email), the phone keeps the session in the secure store, registers itself, and links its local documentary to the account. That link is the first sync handshake; P6 builds the full sync on top of it. The person can ask for their account to be deleted from the app or from a public web page. Everything runs and is tested locally (the Workers test pool, Miniflare's D1); deploying needs the owner's Cloudflare account (P-B) and real Apple, Google and mail credentials, which are owner items.

**Read first:** `CLAUDE.md` (rules 3, 5, 6, 9, 10, 11), `docs/architecture/ARCHITECTURE.md` §2 (`apps/api/src` layers), §3, §5 "Sync", §8, DECISIONS D16, D17, D36, `tasks/p8/T-008.md` "Navigation".

**Stack (checked 2026-09-27 against the npm registry and the packages' type declarations).**
- API (`apps/api`): `better-auth` 1.7.6, `drizzle-orm` 0.45.3, dev `drizzle-kit` 0.31.11 (pin with `~`). Facts from the 1.7.6 types:
  - `betterAuth({ database: drizzleAdapter(db, { provider: 'sqlite', schema, transaction: false }), … })` with `drizzleAdapter` from `better-auth/adapters/drizzle` and `drizzle` from `drizzle-orm/d1`. `transaction` defaults to `false` in 1.7.6 (D1 has no interactive transactions); set it explicitly.
  - `advanced.database.generateId: 'uuid'` makes user, session and account ids UUIDs (our contracts' `Uuid`).
  - `advanced.database.validateSchema: false` skips the start-up schema check (it reads SQLite system tables, which D1 refuses with `SQLITE_AUTH`; in 1.7.6 a failed check is only logged, but it costs a query on every cold start).
  - Email code: the `emailOTP` plugin from `better-auth/plugins/email-otp` with `sendVerificationOTP({ email, otp, type })`, `otpLength` (6), `expiresIn` (seconds; 300), `allowedAttempts` (3), `storeOTP: 'hashed'`; endpoints `POST /email-otp/send-verification-otp` and `POST /sign-in/email-otp`.
  - `expo()` server plugin from `@better-auth/expo` 1.7.6 (it trusts the app scheme and hands the session cookie back to the app after a browser sign-in).
  - The tables Better Auth needs are listed at run time by `getAuthTables(options)` from `@better-auth/core/db`; the Drizzle schema is checked against it in a test instead of trusting a generator (`@better-auth/cli` is at 1.4.21 and trails the core).
  - `@cloudflare/vitest-pool-workers` 0.22 (already present) applies D1 migrations in tests (`readD1Migrations` in the config, `applyD1Migrations` from `cloudflare:test`; check both names in its installed types).
- Mobile (`apps/mobile`, `npx expo install`): `better-auth` 1.7.6 and `@better-auth/expo` 1.7.6 (`expoClient({ scheme, storagePrefix, storage })` from `@better-auth/expo/client`; its peers `expo-secure-store`, `expo-linking`, `expo-web-browser` ~57.0.3, `expo-network` ~57.0.2, `expo-constants`), `expo-apple-authentication` ~57.0.2 (native Sign in with Apple; its identity token goes to `signIn.social({ provider: 'apple', idToken: { token } })`).

**Decided here (DECISIONS D36).** Email sign-in is a six-digit code, not a magic link: it works when the mail is opened on another device, and it needs no hand-off of a browser cookie into the app. User ids are UUIDs. The auth instance is built per request from `env` (Workers have no global env). Mail goes through a `MailSender` port; tests and `wrangler dev` use a recording sender; the real mail vendor is chosen with the owner when the account exists (an owner item, not a blocker for P4). Apple and Google sign-in are configured only when their credentials exist in `env`; tests never call Apple or Google.

**Rules for every P4 task.** Contracts first (rule 3): every request and response body is a Zod schema in `packages/contracts`, parsed on both sides. Only `providers/` imports vendor SDKs (the mail vendor later); Better Auth and Drizzle are infrastructure and live in `auth/` and `data/`. No secret in code, docs, tests or messages (rule 9): `BETTER_AUTH_SECRET`, `APPLE_*`, `GOOGLE_*` are Worker secrets; tests set throwaway values through the test pool's bindings; `.dev.vars.example` holds placeholder names only. No email address, code or token is logged.

**Out of scope.** Uploads and the full `POST /sync` (P6), push tokens and the "episode ready" push (P9 server part), entitlements (P23), crew invites (P19), deploying (P-B), the real mail vendor.

## T-010a · Better Auth on Workers and D1, proved in the test pool · needs T-001c

**Goal.** Better Auth runs inside the Worker on D1 with a six-digit email code, and a test in the Workers pool signs a person in end to end. If it cannot, the task reports the blocker instead of working around it.

**Do.**
1. Install the API stack above. `src/data/schema.ts`: the Drizzle SQLite tables `user`, `session`, `account`, `verification` and `rateLimit` with the fields `getAuthTables(authOptions)` lists for our options (UUID text ids, timestamps as integers in `timestamp_ms` mode or as the adapter expects; check the adapter's docs in its types). `drizzle-kit generate` writes `apps/api/migrations/0000_auth.sql`; `wrangler.jsonc` points `migrations_dir` at it. Migrations are append-only from here on (rule 6).
2. `src/providers/mail/`: `MailSender { send(to, subject, text): Promise<void> }` and `recordingMail()` (keeps the last messages in memory for tests and `wrangler dev`; never prints the code). The words of the mail come from `packages/story/src/words` ("Your Life Documentary code is 123456. It works for 5 minutes.").
3. `src/auth/auth.ts`: `createAuth(env, mail)` with the options above, `rateLimit: { enabled: true, storage: 'database' }`, `trustedOrigins: ['lifedocumentary://']`, `user.deleteUser.enabled: false` (deletion goes through our own 30-day request in T-010b), social providers only when their env values exist. `src/app.ts` mounts `app.on(['GET', 'POST'], '/api/auth/*', …)` handing the raw request to `createAuth(c.env, mail).handler`.
4. `src/shared/env.ts` gains `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` and the optional provider values; `pnpm types:api` regenerates `worker-configuration.d.ts`.

**Tests** (Workers pool, D1 with the migrations applied):
- The Drizzle schema has every table and field `getAuthTables(authOptions)` requires (compare names, not SQL text).
- Sign-in by code: send a code to a new address → the recording mail holds one message with a six-digit code → `POST /api/auth/sign-in/email-otp` with it returns a session cookie → `GET /api/auth/get-session` with that cookie returns the user, whose id is a UUID.
- The same code used a second time fails; a wrong code fails, and after 3 wrong codes the right one fails too.
- No test output, log line or stored row contains the plain code (`storeOTP: 'hashed'`).

**Acceptance.** API typecheck, tests, lint, format, boundaries, `deploy:dry` pass. If Better Auth cannot run on D1 in the pool with the options above, commit nothing that works around it: post `T-010a blocked · Better Auth on D1 · <the error>` (the supervisor then decides on the D17 fallback). UNVERIFIED: Apple and Google sign-in (no credentials), a deployed Worker.

## T-010b · Product rows, devices and the first link · needs T-010a

**Goal.** A signed-in phone registers itself and links its local documentary to the account; the account's deletion can be requested and cancelled.

**Do.**
1. Next migration: `documentaries` (the `Documentary` contract's fields; `owner_user_id` references `user.id`), `devices` (`id` UUID chosen by the phone, `user_id`, `platform` `ios`/`android`, `app_version`, `created_at`, `last_seen_at`), `deletion_requests` (`user_id` primary key, `requested_at`, `purge_after` = requested + 30 days, `cancelled_at`). Repositories in `src/data/repositories/` parse rows with the contracts.
2. `packages/contracts/src/api/account.ts` (exported): `Me` (`userId`, `email`, `documentaries`, `deletion` `{ purgeAfter } | null`), `RegisterDevice` (`id`, `platform`, `appVersion`), `LinkDocumentary` (the local `Documentary`), `LinkDocumentaryResult` (`documentary` as stored).
3. `src/routes/middleware/session.ts`: `requireSession` reads the session with `auth.api.getSession({ headers })`; none → `apiError(401, 'unauthorized')`. Routes: `GET /me`; `POST /devices` (upsert, bumps `last_seen_at`); `POST /documentaries/link`: a new id → stored with `ownerUserId` = the session user; the same id already owned by this user → returned unchanged (idempotent); owned by someone else → `409 conflict`; `POST /account/delete` → a deletion request and every session of the user revoked; `POST /account/delete/cancel` → `cancelled_at` set when still before `purge_after`. Bodies parsed with the contracts; `400 bad_request` on a bad body.
4. Nothing is purged in P4: the purge job is `DeleteJob` (P21). The request row is what P21 acts on.

**Tests** (Workers pool): every route without a session → 401 with the `ApiError` shape; link creates once, returns the same row on a second call, gives 409 to another user; the stored documentary keeps the phone's id and takes the session user as owner; device upsert keeps one row and moves `last_seen_at`; delete request revokes the sessions (the old cookie then gets 401) and `Me.deletion.purgeAfter` is 30 days later; cancel clears it; the migration test: from the auth-only database, the new migration adds the three tables and keeps the auth rows.

**Acceptance.** API and contracts typecheck, tests, lint, format, boundaries, `deploy:dry` pass.

## T-010c · The public deletion page · needs T-010b

**Goal.** App stores require that an account can be deleted without the app; a plain web page on the API does it with the same email code.

**Do.** `src/routes/deletePage.ts`: `GET /account/delete` returns a small HTML page (no script from another origin, no tracking; text from `packages/story/src/words`; readable at 200 % zoom; labels on every field; WCAG 2.2 AA contrast) with an email field; submitting sends a code (the `emailOTP` "sign-in" type) and shows a code field; a correct code signs in for this page only and shows one "Delete my account" button that posts to the same deletion request as T-010b, then a line that the account and everything in it will be deleted on `purgeAfter`, and how to cancel (sign in again in the app within 30 days). Forms post same-origin with the session cookie; the POST handlers check `Origin`.

**Tests** (Workers pool): the page renders its labelled fields; the whole flow with the recording mail creates the deletion request; a wrong code shows the plain error line and creates nothing; a POST with a foreign `Origin` is refused.

**Acceptance.** API typecheck, tests, lint, format, boundaries, `deploy:dry` pass; UNVERIFIED: the page on a real domain.

## T-010d · Sign in on the phone and the first link · needs T-010b, T-009d

**Goal.** Settings gains an Account section: a person signs in with Apple (iPhone), Google or an email code, the session lives in the secure store, the phone registers and links its documentary, and signing out or asking for deletion works.

**Do.**
1. `npx expo install` the mobile stack above; `app.json`: the `expo-apple-authentication` plugin, `ios.usesAppleSignIn: true`, `extra.apiBaseUrl` (`http://localhost:8787` for development; the real URL is an owner item).
2. `src/services/auth/authClient.ts`: `createAuthClient({ baseURL: apiBaseUrl, plugins: [expoClient({ scheme: 'lifedocumentary', storagePrefix: 'life', storage: SecureStore }), emailOTPClient()] })`. `src/domain/capturePorts.ts` gains `Account { session(): Promise<{ userId; email } | null>; sendCode(email); signInWithCode(email, code); signInWithApple(); signInWithGoogle(); signOut(); cookie(): string | null }`; adapter `src/services/auth/betterAuthAccount.ts`; fake in `fakeServices`. `src/services/api/apiClient.ts`: `fetch` against `apiBaseUrl` with the session cookie, every response parsed with the contracts; an `Api` port with `me`, `registerDevice`, `linkDocumentary`, `requestDeletion`, `cancelDeletion`; fake in `fakeServices`.
3. `src/application/account.ts`: `afterSignIn(store, clock, api, documentary, device)` registers the device (a device id created once and kept in `settings`), links the local documentary, and when the server's `ownerUserId` differs from the local one, updates the local row (`updatedAt` bumped) so every later row carries the account's id; failures leave the local documentary untouched and are shown with a `words` line; running it twice changes nothing.
4. Settings, Account section: signed out: "Sign in with Apple" (iPhone only, the `AppleAuthenticationButton` in its black style, as Apple requires), "Continue with Google", and "Email" (a `Field`, "Send code", then a code `Field` and "Sign in"); signed in: the email in `body`, "Sign out", and "Delete account" (asks once; `words` explain 30 days and how to cancel; shows the purge date after). One amber action at most on the screen; the words say that capture works without an account and that an account is for weekly episodes.

**Tests** (RNTL, fake Account and Api, memory store): signing in with a code runs `afterSignIn` once (device registered, documentary linked, local owner id updated); a second `afterSignIn` changes nothing; a failed link leaves the local documentary as it was and shows the line; the Apple button is absent on Android (`Platform.OS` mocked); sign out returns the section to signed out; delete asks, then shows the purge date; the device id is stable across two `afterSignIn` calls.

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; Design Lab "Settings" section shows both Account states; UNVERIFIED: Apple and Google sign-in on a device (owner credentials), the session surviving an app restart on a device.
