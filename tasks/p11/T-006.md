# T-006 · P11 Contracts and the pure story engine

Text for T-006a–c. Published 2026-09-26; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P11.** The shapes between the device, the API, the model and the render for one weekly episode are versioned Zod contracts, and the pure functions around them (the week's brief for the planner, plan validation, the recap plan that guarantees an episode) are tested in `packages/story` against 20 synthetic weeks, before any model or pipeline exists.

**Read first:** `CLAUDE.md`, `docs/architecture/ARCHITECTURE.md` §3, §4 (Week brief, Episode plan, Narration, Edits), §6, §7, DECISIONS D3, D14, D15, D20, D21. The domain contracts from T-004a (`Moment`, `MediaAsset`, `Question`, `Storyline`, `CastMember`, `Episode`, `Timestamp`) are the inputs.

**Versions.** No new dependencies.

**Owners table.**
| Path | Task |
|---|---|
| `packages/contracts/src/episode/**` (plan, brief, derived, edit op) and their tests | T-006a |
| `packages/story/src/shareable.ts`, `packages/story/src/weekBrief/**`, `packages/story/test/fixtures/weeks.ts` and their tests | T-006b |
| `packages/story/src/planValidation/**`, `packages/story/src/recapPlan/**`, `packages/story/src/words/recap.ts` and their tests | T-006c |

**Decisions this text makes (recorded in `docs/COACHING-DECISIONS.md`).**
- `EpisodePlanV1.scenes` allows 1–5 scenes and `targetDurationMs` 20,000–240,000 so that a recap of a sparse week is still a valid plan; a model plan is held to 3–5 scenes and 60,000–240,000 ms by `validatePlan(…, 'model')`.
- A week with no shareable media gets no recap plan (`recapPlan` returns `null`); P16 shows a quiet-week card instead of a failed episode.
- Spoken time of a narrator text is estimated at 400 ms per word (150 words a minute).

**Rules for every task.** Pure code only (no clock, no `Math.random`, no I/O); converting a `Timestamp` to a local date in a given time zone may use `Intl.DateTimeFormat` with an explicit `timeZone`. Every function's output is parsed with its contract in the tests. `localOnly` and deleted moments never appear in a brief or a plan (ARCHITECTURE §7).

**Out of scope.** Model calls, prompts and the evaluation runner (P13), narration (P14), mapping a plan to a `RenderManifest` (P15), edit operations as functions (P17), sync DTOs (P6).

## T-006a · Episode contracts · needs T-004a

**Goal.** `EpisodePlanV1`, `WeekBriefV1`, `Derived` and `EditOp` exist as contracts with tests.

**Do.** In `packages/contracts/src/episode/`, exported from the package index:
1. `MusicMood = z.enum(['calm', 'warm', 'bright', 'bittersweet', 'driving'])`; `KenBurns` = the photo `kenBurns` object of `RenderManifestV1` (reuse it; move it to a shared const if needed without changing `RenderManifestV1`'s behaviour).
2. `EpisodePlanV1`:
   ```ts
   z.object({
     version: z.literal(1),
     title: z.string().min(1).max(60), subtitle: z.string().min(1).max(80).optional(),
     episodeNumber: z.number().int().min(1), weekStart: LocalDate, weekEnd: LocalDate,
     coldOpen: z.object({ momentId: Uuid, inMs: z.number().int().min(0), outMs: z.number().int().min(1) }),
     scenes: z.array(z.object({
       heading: z.string().min(1).max(60), storylineId: Uuid.optional(),
       shots: z.array(z.object({ momentId: Uuid, inMs: z.number().int().min(0).optional(),
                                 outMs: z.number().int().min(1).optional(), kenBurns: KenBurns.optional() })).min(1).max(6),
       narratorBridge: z.object({ text: z.string().min(1).max(140) }).optional(),
       captionsFromTranscript: z.boolean(),
     })).min(1).max(5),
     closing: z.object({ momentId: Uuid }),
     tease: z.object({ storylineId: Uuid, text: z.string().min(1).max(100) }).optional(),
     music: z.object({ mood: MusicMood, trackId: z.string().min(1).optional() }),
     lowerThirds: z.array(z.object({ momentId: Uuid, castId: Uuid, atMs: z.number().int().min(0) })).max(20),
     narratorVoiceId: z.string().min(1).max(40).optional(),
     targetDurationMs: z.number().int().min(20000).max(240000),
     summary: z.string().min(1).max(400),
   })
   ```
   with refinements: `coldOpen.outMs > coldOpen.inMs`; a shot with both `inMs` and `outMs` has `outMs > inMs`; `weekEnd` is `weekStart` + 6 days.
3. `WeekBriefV1`:
   ```ts
   z.object({
     version: z.literal(1),
     documentaryId: Uuid, episodeNumber: z.number().int().min(1),
     weekStart: LocalDate, weekEnd: LocalDate, timeZone: IanaTimeZone,
     moments: z.array(z.object({
       momentId: Uuid, day: LocalDate, kind: MomentKind, durationMs: z.number().int().min(0).optional(),
       questionText: z.string().optional(), transcript: z.string().optional(), caption: z.string().optional(),
       text: z.string().optional(), mood: MomentMood.optional(), placeName: z.string().optional(),
       storylineIds: z.array(Uuid), castIds: z.array(Uuid),
     })).max(300),
     storylines: z.array(z.object({ id: Uuid, title: z.string(), open: z.boolean() })),
     cast: z.array(z.object({ id: Uuid, name: z.string(), relation: z.string().optional() })),
     previousSummaries: z.array(z.string().max(400)).max(3),
     questionsAsked: z.array(z.object({ day: LocalDate, text: z.string(), answered: z.boolean() })).max(7),
   })
   ```
   (`MomentKind`, `MomentMood`, `IanaTimeZone` come from the existing contracts.)
4. `Derived = z.object({ momentId: Uuid, transcript: z.string().max(4000).optional(), caption: z.string().max(500).optional(), language: z.string().min(2).max(12), provider: z.enum(['workersAi', 'anthropic']), modelVersion: z.string().min(1), producedAt: Timestamp })`, refined so at least one of `transcript` or `caption` is present.
5. `EditOp`: `{ id: Uuid, episodeId: Uuid, seq: int ≥ 1, appliedToVersion: int ≥ 1, op }` where `op` is a discriminated union on `kind`: `retitle { title 1..60 }`, `swapLine { sceneIndex int ≥ 0, with: { kind: 'moment', momentId, inMs?, outMs? } | { kind: 'bridge', text 1..140 } }`, `dropClip { sceneIndex, shotIndex }`, `closingShot { momentId }`, `musicMood { mood: MusicMood }`.

**Tests** (`packages/contracts/test/episode.test.ts`): a valid plan with 3 scenes parses; rejects 0 and 6 scenes, a scene with 0 or 7 shots, `coldOpen.outMs <= inMs`, a 141-character bridge, `targetDurationMs` 19,999, `weekEnd` ≠ `weekStart` + 6. A valid brief parses and a brief with 301 moments does not. `Derived` without transcript and caption is rejected. Each `EditOp` kind parses once; an unknown kind is rejected.

**Acceptance.** Contracts tests, typecheck, lint, format, boundaries pass; `RenderManifestV1` tests unchanged and green.

## T-006b · The shareable rule, the week brief and 20 synthetic weeks · needs T-006a

**Goal.** `weekBrief(input)` builds the planner's `WeekBriefV1` from device rows, deterministically, never including a `localOnly` or deleted moment, within a size budget; 20 synthetic weeks exist as fixtures for every later story test and the P13 evaluation set.

**Do.**
1. `packages/story/src/shareable.ts`: `isShareable(moment: Moment): boolean` = not `localOnly` and no `deletedAt`. This is the one rule for "may this moment's metadata leave the device"; P6's `leavesDevice(moment, entitlement)` will build on it. Also `localDay(timestamp: Timestamp, timeZone: string): LocalDate`.
2. `packages/story/src/weekBrief/weekBrief.ts`, exported from the package index: `weekBrief(input): WeekBriefV1` where `input = { documentaryId, episodeNumber, weekStart, timeZone, moments: Moment[], mediaAssets: MediaAsset[], derived: Derived[], questions: Question[], storylines: Storyline[], cast: CastMember[], previousSummaries: string[] }`.
   - Moments: shareable, with `localDay(capturedAt, moment.timeZone)` inside `[weekStart, weekStart + 6]`, sorted by `capturedAt` then `id`. `durationMs` from the moment's media asset; `questionText` from its question; `transcript`/`caption` from `Derived` (transcript cut to 1,200 characters and caption to 300 at a word boundary, ending with "…" when cut).
   - `storylines`: those referenced by an included moment or open during the week (`openedAt` day ≤ `weekEnd` and no `closedAt` before `weekStart`), sorted by title then id; `cast`: those referenced by an included moment, sorted by name then id; ids that reference nothing known are dropped from a moment's lists.
   - `questionsAsked`: the week's questions by `askedOn`, `answered` = `answeredByMomentId` points to an included moment.
   - `previousSummaries`: the last three given, oldest first.
   - Budget: if `JSON.stringify(brief).length > 60000`, drop moments in this order until it fits: notes, then photos, then clips, then answers; within a kind, the earliest first. (60,000 characters ≈ 15k tokens.)
   - The result is returned through `WeekBriefV1.parse`.
3. `packages/story/test/fixtures/weeks.ts`: `fixtureWeeks(): FixtureWeek[]`, 20 pure, deterministic weeks (fixed UUIDs, no randomness) of device rows in the `weekBrief` input shape, covering at least: a full week (7 answers, clips, photos, notes); a quiet week (no moments); a single-answer week; a photos-only week; a week where 3 moments are `localOnly` and 1 is deleted; two open storylines and four cast members; a week crossing the European DST change (`Europe/Dublin`, 2026-10-25) and one in `Asia/Manila`; moments captured just before and after local midnight; a heavy week (220 moments with long transcripts) that exceeds the budget; a week whose answers have no `Derived` yet. Name each week in the fixture.

**Tests** (`packages/story/test/weekBrief.test.ts`, `shareable.test.ts`):
- `isShareable`: false for `localOnly`, false for deleted, true otherwise. `localDay` of `2026-10-24T23:30:00Z` is `2026-10-25` in `Europe/Dublin` and `2026-10-25` in `Asia/Manila`, and `2026-10-25T23:30:00Z` is `2026-10-25` in `Europe/Dublin` (after the change back to GMT).
- Every fixture week produces a brief that parses with `WeekBriefV1`.
- No `localOnly` or deleted moment id appears anywhere in `JSON.stringify(brief)` for the localOnly week.
- Moments just before and after local midnight land on the correct days; a moment of the following Monday (local) is excluded.
- The heavy week fits in 60,000 characters, keeps all its answers, and drops notes first.
- Long transcripts are cut to 1,200 characters ending with "…"; the same input gives the same brief twice.

**Acceptance.** Story tests, typecheck, lint, format, boundaries pass; `packages/story` imports only `@life/contracts` and `zod`.

## T-006c · Plan validation and the recap plan · needs T-006b

**Goal.** `validatePlan(plan, brief, mode)` enforces the product rules on a plan, and `recapPlan(brief)` always gives a valid plan (titles, music, the footage, no narrator) for a week with any shareable media.

**Do.**
1. `packages/story/src/planValidation/validatePlan.ts`, exported from the package index: `validatePlan(plan: EpisodePlanV1, brief: WeekBriefV1, mode: 'model' | 'recap'): { ok: true } | { ok: false; errors: string[] }` (reuse the `TimelineResult` shape). Errors (one message each, naming the scene/shot index):
   - a `momentId` (cold open, shots, closing, lower thirds) that is not in `brief.moments`;
   - `weekStart`, `weekEnd` or `episodeNumber` different from the brief's;
   - a `storylineId` (scene or tease) not in `brief.storylines`; a lower third whose `castId` is not in `brief.cast` or not in that moment's `castIds`;
   - an `outMs` beyond the moment's `durationMs` when the duration is known;
   - `mode === 'model'`: fewer than 3 scenes; `targetDurationMs` outside 60,000–240,000; the cold open is not an `answer`; a narrator bridge or tease without `narratorVoiceId`; narrator time above 25% of spoken time, where narrator time = 400 ms × words of every bridge and the tease, and spoken time = narrator time + the cold open's `outMs − inMs` + for every shot of an `answer` moment `(outMs ?? durationMs) − (inMs ?? 0)`;
   - `mode === 'recap'`: any narrator bridge, tease or `narratorVoiceId`.
2. `packages/story/src/words/recap.ts` (exported through `words`): the recap title `The week of {date}` (date as "14 September"), the summary `A recap of the week of {start} to {end}.`, weekday headings `Monday`…`Sunday`, and a merged heading `{first} to {last}` ("Monday to Wednesday"). Plain; no exclamation marks.
3. `packages/story/src/recapPlan/recapPlan.ts`, exported from the package index: `recapPlan(brief: WeekBriefV1): EpisodePlanV1 | null`. `null` when the brief has no moment of kind `answer`, `clip` or `photo`. Otherwise, deterministically:
   - media moments in brief order; the cold open is the first `answer` (its whole duration, or 0–6,000 ms when unknown), else the first media moment (a photo 0–3,000 ms, a clip 0–min(duration, 6,000) ms);
   - one scene per day that has media, heading = the weekday word; while there are more than 5 scenes, merge the adjacent pair with the fewest shots combined (the earliest pair on a tie; a merged scene's heading uses the merged-heading words for its first and last day); a scene keeps at most 6 shots (answers first, then by brief order); photos get `kenBurns: { fromScale: 1, toScale: 1.06 }` (DESIGN §2 `texture.kenBurns`), written as named constants in `recapPlan.ts` because `packages/story` must not import `@life/design`;
   - `captionsFromTranscript: true` on every scene; no bridges, no tease, no `narratorVoiceId`, no lower thirds;
   - closing = the last media moment; music mood `calm`; title and summary from `words`;
   - `targetDurationMs` = 3,000 (title) + Σ shot lengths (answer: its duration or 6,000; clip: min(duration, 6,000); photo: 3,000) + 2,500 (closing), clamped to 20,000–240,000.
   The result is returned through `EpisodePlanV1.parse`.

**Tests** (`packages/story/test/planValidation.test.ts`, `recapPlan.test.ts`):
- A hand-written valid model plan for the full fixture week passes in `model` mode; one test per error in Do 1 (each changes one thing in that plan and expects exactly that error).
- The 25% rule: a plan with narrator time exactly 25% passes; one word more fails.
- `recapPlan` for every fixture week: `null` exactly for the weeks without media; otherwise it parses, passes `validatePlan(…, 'recap')`, uses only moment ids from the brief, has at most 5 scenes and 6 shots per scene, and gives the same plan twice.
- The full week's recap has 5 scenes after merging (the fixture has media on 7 days); the single-answer week's recap has 1 scene and the answer as cold open.

**Acceptance.** Story tests, typecheck, lint, format, boundaries pass; `packages/story` imports only `@life/contracts` and `zod`; no clock or randomness in `packages/story/src`.
