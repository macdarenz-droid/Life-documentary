# T-002 · P-A Render proof

Text for T-002a–b. Published 2026-09-26; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**What this proves.** A Remotion composition turns a typed `RenderManifest` into a watchable 1080×1920 MP4 with a title card, a video shot, a photo with a slow push-in (Ken Burns), a narrator line with captions, a name lower-third, a music bed that ducks under speech, and a closing card, locally and in CI, in under 3 minutes on the CI runner. If this fails, DECISIONS D9's fallback (FFmpeg templates) applies, so report honestly.

**Read first:** `CLAUDE.md`, `docs/architecture/ARCHITECTURE.md` §4 (Render) and §7, DECISIONS D9, D13, D25. Remotion docs: fundamentals, `<OffthreadVideo>`, `<Img>`, `<Audio>` with a `volume` callback, `<Sequence>`, `calculateMetadata`, Zod props schema, `renderMedia`/CLI render, and the "GitHub Actions" guide. Remotion's official agent skills are allowed reading.

**Versions.** `remotion`, `@remotion/cli`, `@remotion/bundler`, `@remotion/renderer`, `@remotion/zod-types` all at the same exact `4.0.529` (Remotion requires identical versions). React as Remotion 4.0.529 supports (state the version under Decisions).

**Owners table.**
| Path | Task |

| `packages/story/src/render/` | T-002a |

**Fixture media rule.** No downloaded media and no media with a licence. Every fixture is generated in the repo by code: video and photo by rendering small Remotion fixture compositions, audio by a Node script that writes PCM WAV. Generated files go to `packages/render/public/fixtures/` and are **not** committed (they are generated before render, locally and in CI).

**Headless browser.** In CI use Remotion's own `npx remotion browser ensure`. In a cloud container where the download is blocked, pass `--browser-executable /opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` through an env var `REMOTION_BROWSER_EXECUTABLE` that the scripts read when set. Never hard-code the path.

**Out of scope.** Remotion Lambda, AWS, narration synthesis, real music, 16:9 format, the full `EpisodePlan`.

## T-002a · RenderManifest v1 and its timeline rules · needs T-001a

**Goal.** The render input is a validated contract, and the timeline arithmetic the composition needs is pure, tested code outside the renderer.

**Do.**
1. `packages/contracts/src/render/renderManifest.ts`, exported from the package index:
   ```ts
   RenderManifestV1 = z.object({
     version: z.literal(1),
     format: z.object({ width: z.literal(1080), height: z.literal(1920), fps: z.literal(30) }),
     title: z.object({ text: z.string().min(1).max(80), subtitle: z.string().min(1).max(80).optional(), durationMs: z.number().int().min(1000).max(6000) }),
     shots: z.array(z.discriminatedUnion('kind', [
       z.object({ kind: z.literal('video'), src: z.string().min(1), durationMs: z.number().int().min(500).max(15000), inMs: z.number().int().min(0).default(0) }),
       z.object({ kind: z.literal('photo'), src: z.string().min(1), durationMs: z.number().int().min(500).max(10000),
                  kenBurns: z.object({ fromScale: z.number().min(1).max(1.5), toScale: z.number().min(1).max(1.5) }).optional() }),
     ])).min(1).max(40),
     narration: z.array(z.object({ src: z.string().min(1), atMs: z.number().int().min(0), durationMs: z.number().int().min(200), text: z.string().min(1).max(280) })).max(20),
     captions: z.array(z.object({ fromMs: z.number().int().min(0), toMs: z.number().int().min(1), text: z.string().min(1).max(120) })).max(200),
     lowerThirds: z.array(z.object({ atMs: z.number().int().min(0), durationMs: z.number().int().min(1000).max(6000), name: z.string().min(1).max(40), relation: z.string().min(1).max(40).optional() })).max(20),
     music: z.object({ src: z.string().min(1), gain: z.number().min(0).max(1), duckTo: z.number().min(0).max(1) }).optional(),
     closing: z.object({ text: z.string().min(1).max(80), durationMs: z.number().int().min(1000).max(6000) }),
     credit: z.literal('AI-narrated'),
   })
   ```
   `src` values are URLs or paths relative to the render project's `public/` (the composition resolves them with `staticFile` when they do not start with `http`).
2. `packages/story/src/render/timeline.ts`, exported from the package index:
   - `manifestDurationMs(m)`: title + sum of shot durations + closing.
   - `shotStartsMs(m)`: start time of each shot (the first shot starts at `title.durationMs`).
   - `msToFrames(ms, fps)`: `Math.round(ms * fps / 1000)`.
   - `validateTimeline(m)`: returns `{ ok: true } | { ok: false, errors: string[] }`; errors when a caption or narration or lower-third ends after `manifestDurationMs`, a caption has `toMs <= fromMs`, two narration items overlap, or two captions overlap. Intervals are half-open `[start, end)`: items that only touch do not overlap.
   - `musicVolumeAt(ms, m)`: `0` when there is no music; otherwise `m.music.duckTo` inside any narration interval, `m.music.gain` farther than 300 ms from any narration interval, linear ramp in the 300 ms before and after each interval; separately a fade envelope that rises linearly from 0 to 1 over the first 1,000 ms and falls linearly to 0 over the last 1,500 ms of `manifestDurationMs`. The result is `min(duckingValue, gain × envelope)`.
3. `packages/story/src/render/fixtureManifest.ts`: `fixtureManifest()` returns a valid 30-second-or-shorter manifest that uses `fixtures/clip.mp4` (video, 4,000 ms), `fixtures/photo.jpg` (photo, 4,000 ms, kenBurns 1.0 → 1.12), `fixtures/clip.mp4` again from `inMs: 1000` (3,000 ms), one narration `fixtures/voice.wav` at 5,000 ms for 2,500 ms with its text, two captions that split the narration text in two and cover 5,000–6,250 ms and 6,250–7,500 ms, one lower-third "Maya · sister" at 9,000 ms for 3,000 ms, music `fixtures/music.wav` gain 0.6 duckTo 0.15, title "Episode 1 · The Week It Rained" subtitle "12–18 October" for 3,000 ms, closing "See you next week." 2,500 ms, credit `'AI-narrated'`.

**Tests** (`packages/contracts/test/renderManifest.test.ts`, `packages/story/test/timeline.test.ts`):
- `fixtureManifest()` parses with `RenderManifestV1` and passes `validateTimeline`.
- Rejects: a 1920×1080 format; an empty `shots`; a missing `credit`.
- `manifestDurationMs(fixtureManifest())` equals the hand-computed value; `shotStartsMs` equals the hand-computed list.
- `validateTimeline` reports each error kind listed in Do 2 (one test each).
- `musicVolumeAt`: 0 at 0 ms; gain at a point 2 s from any narration and 2 s from either end; duckTo in the middle of the narration; strictly between duckTo and gain 150 ms before the narration starts; 0 at the last millisecond; 0 everywhere with no music.
- `msToFrames(1000, 30) === 30`, `msToFrames(33, 30) === 1`.

**Acceptance.** Package tests, typecheck, lint and `pnpm boundaries` pass; `packages/story` still imports only `@life/contracts` and `zod`.

## T-002b · The render package, fixtures and the CI render job · needs T-002a, T-001d

**Goal.** `pnpm --filter @life/render render:fixture` generates the fixtures, renders `out/fixture.mp4` from `fixtureManifest()`, and verifies the output; CI runs it and uploads the MP4.

**Do.**
1. `packages/render` (`@life/render`): Remotion project. `src/index.ts` calls `registerRoot`. `src/Root.tsx` registers:
   - `Episode` composition: `schema` = `RenderManifestV1`, `defaultProps` = `fixtureManifest()`, `calculateMetadata` returns `durationInFrames = msToFrames(manifestDurationMs(props), 30)`, `width 1080`, `height 1920`, `fps 30`.
   - `FixtureClip` (3 s at 30 fps, 1080×1920): an animated gradient using `@life/design` colours with a large moving frame counter; used only to make `clip.mp4`.
   - `FixturePhoto` (still, 1080×1920): a static composition with shapes and the text "Photo fixture"; used only to make `photo.jpg`.
2. Components in `src/episode/`: `TitleCard`, `VideoShot` (`OffthreadVideo`, `startFrom` from `inMs`, `objectFit: cover`, muted), `PhotoShot` (`Img` scaled from `fromScale` to `toScale` across the shot with `interpolate`), `Captions` (bottom safe area, max two lines, `tokens.color.text` on a translucent `tokens.color.background` band), `LowerThird` (name and relation, slides in and out over 250 ms; no motion when a `reducedMotion` prop is true — default false), `ClosingCard` with the `credit` line "AI-narrated" in small type, `Narration` (`Audio` per item in a `Sequence`), `Music` (`Audio` with `volume={(f) => musicVolumeAt(f * 1000 / fps, manifest)}`). Colours, sizes and durations only from `@life/design` and the manifest. Fonts: system sans for now.
3. `scripts/make-fixtures.mts` (run with `tsx`): writes `public/fixtures/voice.wav` (2.5 s, 48 kHz mono 16-bit, a 220 Hz tone shaped by a 4 Hz amplitude envelope so it reads as speech-like) and `public/fixtures/music.wav` (32 s, 48 kHz stereo, a soft chord of three sine tones), then renders `FixtureClip` to `public/fixtures/clip.mp4` and `FixturePhoto` to `public/fixtures/photo.jpg` with the Remotion CLI or `@remotion/renderer`. Idempotent: skips files that exist unless `--force`.
4. `scripts/render-fixture.mts`: bundles, renders `Episode` with `defaultProps` to `out/fixture.mp4` (H.264, CRF 23), then verifies with Remotion's ffprobe (`npx remotion ffprobe` or `@remotion/renderer` media parsing): width 1080, height 1920, duration within ±200 ms of `manifestDurationMs`, has an audio stream. Exits 1 with a clear message when any check fails. Prints the elapsed render time.
5. Scripts in `package.json`: `studio` (`remotion studio`), `fixtures` (`tsx scripts/make-fixtures.mts`), `render:fixture` (`pnpm fixtures && tsx scripts/render-fixture.mts`), `typecheck`, `test` (Vitest for any pure helpers inside the package, e.g. a `resolveSrc` helper), `lint` via root. Both scripts honour `REMOTION_BROWSER_EXECUTABLE`.
6. `.gitignore` adds `packages/render/public/fixtures/` and `packages/render/out/`.
7. CI: a second job `render` in `.github/workflows/ci.yml` (needs `checks`), same setup steps, then `pnpm --filter @life/render exec remotion browser ensure`, then `pnpm --filter @life/render render:fixture`, then `actions/upload-artifact` of `packages/render/out/fixture.mp4` (retention 7 days). Timeout 15 minutes. Install any Linux libraries the Remotion GitHub Actions guide lists.

**Tests.**
- `packages/render/test/resolveSrc.test.ts`: `http…` sources are returned unchanged; relative sources go through the same function the composition uses (mock `staticFile` if needed).
- The render verification in Do 4 is the behaviour test for the composition; it runs in CI.

**Acceptance.**
- Locally: `pnpm --filter @life/render render:fixture` succeeds and prints the verification lines and the elapsed time (report the time and machine).
- CI: both jobs green; the `fixture.mp4` artifact exists; the `render` job's render step takes under 3 minutes (report the number from the log).
- Report under "UI visible" the artifact name so the supervisor can watch it.
- No committed binaries; no network media; the composition reads colours only from `@life/design`.
