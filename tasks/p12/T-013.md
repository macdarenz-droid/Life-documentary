# T-013 · P12 Understanding

Text for T-013a–e. Published 2026-09-27; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P12.** For one documentary and one week, the server turns what the phone uploaded into text: a transcript for each answer, a caption for each photo and for one keyframe of each video. That text is stored as `Derived` rows, synced down to the phone, and the uploaded working copies are deleted. It runs as step 1 of `EpisodePipeline`, a Cloudflare Workflow; P13 adds the planner after it and P16 the weekly start. Model calls go through ports, so everything here is built and tested with fixture providers; the real calls need the owner's Cloudflare account and Anthropic key and are checked at deploy.

**Read first:** `CLAUDE.md` (rules 2, 3, 4, 5, 6, 7, 8, 9, 10), `docs/VISION.md` §8, `docs/architecture/ARCHITECTURE.md` §3, §5 "Episode", §6, §7, DECISIONS D5, D10, D11, D14, D20, D34, D37, D38, `tasks/p6/T-011.md` (the upload and sync shapes this builds on) and the T-011b and T-011d fix lists in `tasks/TASKS.md`.

**Decided here (DECISIONS D38).**
- **Where and when.** `EpisodePipeline` is a Workflow with one instance per documentary and week (instance id `ep-{documentaryId}-{weekStart}`). Its first step is "understand". P12 starts instances only from `startEpisodePipeline(env, documentaryId, weekStart)` and tests; the cron is P16. Asking the phone for full clips is P16 (per the roadmap; T-011's "P12 requests" is superseded).
- **What it reads.** The week's moments (`localDay(capturedAt, timeZone)` from `@life/story`, the rule `weekBrief` uses, from `weekStart` to `weekStart + 6`; not deleted) that `leavesDevice` allows, and for each the working copies that exist in R2 at their fixed keys. What is not there yet is simply missing (rule 10).
- **Keyframes.** A Worker cannot decode video, so the phone makes the keyframe: the frame at the middle of the video (`durationMs / 2`), longest side 1,000 px, JPEG 0.8, uploaded as a working copy with purpose `keyframe`. Video answers upload `answer` and `keyframe`; voice answers `answer`; photos `preview`; library clips `keyframe`; notes nothing. With Cloud backup (P23) `original` is added to the list, never instead of it.
- **Transcripts.** Workers AI `@cf/openai/whisper-large-v3-turbo`, one call per answer, the working copy streamed from R2 with its stored content type (`{ audio: { body, contentType }, vad_filter: true }`), language detected by the model. An empty transcript writes nothing. Which containers Workers AI accepts is not documented: a real `.m4a` voice answer and a real `.mov` video answer are checked at deploy (owner item); if video is refused, the fallback is decided then.
- **Captions.** Claude Haiku 4.5 (`claude-haiku-4-5-20251001`, one constant) through the Message Batches API (half price; results in any order, keyed by `custom_id` = the moment id). The prompt is fixed below. A caption is kept only when the model ended normally (`end_turn`), the text is not `unclear`, and it contains none of the words of rule 7's list in `policy/captions.ts`; otherwise the moment has no caption. The run waits for the batches up to 2 hours after they are sent, checking every 5 minutes; then it cancels what is unfinished, waits up to 30 more minutes for the cancelled batches to end, reads whatever succeeded, and goes on without the rest. Every batch that has ended is then deleted at Anthropic (batches keep inputs and outputs 29 days unless deleted, and are not zero-retention; a batch can be deleted only once it has ended). Sending a batch is never retried by the Workflow (the SDK already retries a failed connection), so a failure can never leave a second, forgotten batch; a batch that could not be sent means no captions for its images.
- **Working copies.** Every working copy the run looked at is deleted from R2 when the text steps end, whether or not text came from it (the next run covers a different week, so keeping them serves nothing). The backstop is an R2 lifecycle rule on `tmp/` that deletes after 9 days (an owner deploy item): the run reads a whole week once, on Sunday, so D14's 2 days would delete Monday's uploads before they are read. A daily run (P16 can start one) would let the backstop shrink again.
- **Derived rows.** One row per moment and provider (`workersAi` has the transcript, `anthropic` the caption), replaced when the same pair is derived again. They sync down only; a phone never pushes one. A moment's tombstone deletes its derived rows on both sides.
- **Costs.** One ledger row per episode, step and unit, in micro-dollars (µUSD, integers): transcripts by audio second at 513 µUSD per minute; captions by input and output token at the Haiku 4.5 batch prices (0.5 µUSD and 2.5 µUSD per token). `Episode.costCents` = the rounded-up sum of the episode's rows / 10,000. Prices live in `apps/api/src/policy/costs.ts`.
- **Fixtures only when asked.** The Worker uses fixture providers only when its `PROVIDERS` var is `fixture` (the test pool and local dev set it). Without that var and without the key, a model step fails: it never invents text.

## T-013a · Keyframes leave the phone · needs T-011e, T-011d

**Goal.** Every video that may leave the phone also sends one small keyframe, so the server has an image to caption for clips and video answers.

**Do.**
1. `UploadPurpose` gains `keyframe`. `leavesDevice(moment, { cloudBackup })` returns `{ row: boolean; uploads: UploadPurpose[] }` instead of `media`; every caller moves to the list (the phone's sync and enqueue, the server's upload check: a purpose is allowed only when it is in the list). The table: `localOnly` → `{ row: false, uploads: [] }`; no media → `[]`; video answer → `['answer', 'keyframe']` and voice answer → `['answer']`, with or without Cloud backup (the answer upload is the whole file as recorded); photo → `['preview']`, with backup `['preview', 'original']`; clip → `['keyframe']`, with backup `['keyframe', 'original']`; note → `[]`. `DOMAIN_SCHEMA_VERSION` does not change (T-011e's `upload_jobs.purpose` has no CHECK list, per its note).
2. The working-copy key function moves from `apps/api/src/routes/uploads.ts` to `apps/api/src/data/mediaKeys.ts` (`mediaKey(userId, documentaryId, assetId, purpose)`), unchanged in what it returns; `keyframe` is a working copy (`tmp/` prefix). The pipeline (T-013d) imports it from there.
3. `PosterMaker.fromVideo(uri, atMs, maxSide)` takes `maxSide` as a required argument and honours it; `application/posters.ts` passes 480 as posters do today. `enqueueUploads` adds a `keyframe` job for a video when the rule lists it: the frame at `durationMs / 2` (0 when the duration is unknown), longest side 1,000 px, encoded, encrypted into the store and recorded as the job's source exactly like T-011e's photo preview (same quality); content type `image/jpeg`. A frame that cannot be made means no keyframe job (the answer's own job still goes). Existing video captures are enqueued once for their keyframe by the same rule on the first run after this change.

**Tests.** `leavesDevice` table test over kind × asset kind × `localOnly` × `cloudBackup` with exactly the lists in Do 1; a video answer enqueues two jobs and the fake poster maker records `maxSide` 1000 and `atMs` half the duration; a library clip enqueues only a keyframe; a failed frame leaves only the answer job; posters still ask for 480; the server accepts `keyframe` for a clip and refuses `answer` for it, and refuses everything for a `localOnly` moment; a completed keyframe's object key starts with `tmp/{userId}/`.
Allowed test changes: tests that read `media` switch to `uploads` (a photo with backup now also lists `preview`); T-011e's "a clip enqueues nothing" becomes "a clip enqueues only a keyframe"; the poster tests pass `maxSide` 480 explicitly.

**Acceptance.** Story, contracts, mobile and API typecheck, tests, lint, format, boundaries pass; API `deploy:dry` passes. UNVERIFIED on a device: the keyframe's time and size.

## T-013d · EpisodePipeline step 1: understand · needs T-013a, T-013b, T-013c

**Goal.** Starting the pipeline for a documentary's week transcribes its answers, captions its photos and keyframes, stores the text, records the cost, deletes the working copies, and leaves the episode in `planning` for P13.

**Do.**
1. `apps/api/src/pipeline/understand/*.ts`, plain functions over `{ db, media, transcriber, captioner, clock, ids }` so they can be tested without a Workflow: `inventory(episode)` (the week's moments by the "What it reads" line, `leavesDevice` on each, the working copies that exist in R2 by `mediaKey` and `head`, with content type and size; returns ids, keys and kinds only); `transcribeAnswer(item)` (stream the object into the transcriber, write the `workersAi` derived row with the text cut to 4,000 characters and the detected language or `und`, nothing when the text is empty; returns the seconds Whisper reports, or the asset's `durationMs` / 1000 when it reports none); `captionChunks(items)` (split the images into chunks of at most 100 images and at most 12 MB of image bytes, skipping any image over 1.5 MB, so one request body stays well inside a Worker's 128 MB); `submitCaptions(chunk)` (read the chunk's images and send one batch; returns its id); `readCaptions(batchIds)` (keep a caption only by `policy/captions.ts`, write the `anthropic` derived row with language `en`; returns kept and dropped counts and token sums); `removeWorkingCopies(items)`; `recordCosts(episode, usage)` (ledger upserts by `policy/costs.ts`, a unit's row only when its units are above 0, audio units = ⌈Σ seconds⌉; then `costCents` from all the episode's rows). A derived row is written only while its moment exists and is not deleted.
2. `apps/api/src/policy/captions.ts`: `keptCaption(text, stopReason)` → the trimmed text, or null when the stop reason is not `end_turn`, the text is empty or `unclear`, is longer than 300 characters, or contains (as a whole word, any case) one of: man, men, woman, women, boy, boys, girl, girls, guy, guys, lady, ladies, gentleman, gentlemen, he, she, him, her, his, hers, himself, herself, male, female, mother, father, mum, mom, dad, son, daughter, wife, husband, grandmother, grandfather, old, older, elderly, young, younger, teen, teenage, teenager, toddler, baby, babies, child, children, kid, kids, happy, sad, angry, upset, smiling, smiles, smile, laughing, crying, tears, excited, worried, bored, tired, lonely, proud.
3. `apps/api/src/pipeline/EpisodePipeline.ts`: the Workflow, steps in this order: `episode` (get or create, state `understanding`); `inventory`; one `captions-submit-{i}` per chunk (`retries: { limit: 0 }`; `run` catches a failure and goes on without that chunk's captions); one `transcribe-{momentId}` per answer (`retries: { limit: 1 }`, two attempts in all, timeout 2 minutes; `run` catches a step that still fails, leaves that answer without a transcript and goes on); then rounds `captions-wait-{n}` (5 minutes) and `captions-check-{n}` until every sent batch has ended or 24 rounds have passed; `captions-cancel` for the unfinished, then rounds `captions-ending-{n}` / `captions-ending-check-{n}` (5 minutes, at most 6) until they have ended; `captions-read` for every ended batch; `captions-delete` (delete every ended batch at Anthropic; one still not ended is logged by id); `working-copies` (delete every key from `inventory`); `costs`; `planning` (state). Every step is idempotent: a replayed step writes the same rows. `startEpisodePipeline(env, documentaryId, weekStart)` creates the instance `ep-{documentaryId}-{weekStart}` with the week as params, or returns the running one.
4. The `workflows` binding in `wrangler.jsonc` and the class exported from the Worker's main module; `pnpm types:api`, `pnpm format`.

**Tests** (Workers pool, D1 and R2 in Miniflare, fixture providers). Workflow (introspection, sleeps disabled): the run ends `complete` with the episode in `planning` and its `costCents` set; a batch that never ends is checked 24 times, cancelled, deleted once the fake reports it ended, and the run completes with no captions and the transcripts kept; a transcribe step that fails on every attempt leaves that answer without a transcript and the rest done; when the captioner throws `Captioning is not set up` at submit (the fixture set to fail as the real one does without a key), the run still completes with its transcripts and no captions; `startEpisodePipeline` twice for the same week makes one instance.

**Acceptance.** API, contracts and story typecheck, tests, lint, format, boundaries, `deploy:dry` pass. UNVERIFIED until the owner's accounts (owner items): Whisper on a real `.m4a` and `.mov` answer, a real batch of captions, deletion of the batch at Anthropic, the `tmp/` lifecycle rule.

## T-013e · What was understood, on the phone · needs T-013b, T-011e

**Goal.** The phone keeps the transcripts and captions of its own moments, forgets them with the moment, and shows an answer's transcript when it is played.

**Do.**
1. The next device migration: a `derived` table (the contract's fields; unique `(moment_id, provider)`), with its migration test; `DOMAIN_SCHEMA_VERSION` up by one. `src/data/repositories/derived.ts`: `put`, `forMoment`, `deleteForMoment`.
2. `syncNow` lands pulled `derived` rows (replacing T-013b's skip): only when the moment is on this phone, and only when newer by `producedAt` than the stored row for the same moment and provider; a pulled moment tombstone deletes the moment's derived rows. Derived rows are never pushed.
