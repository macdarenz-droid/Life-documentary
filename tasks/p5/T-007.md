# T-007 · P5 Capture

Text for T-007a–d. Published 2026-09-26; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P5.** The heart of the daily loop works on the device: the Today screen shows today's question, the person holds to answer with 10 seconds of video or voice, can add a photo, a clip or photo from the library, a one-line note, a mood and (if they allow it) a place name, and every capture is written encrypted to the file store and as rows in the local database in one step. Nothing leaves the device in P5 (uploads are P6).

**Read first:** `CLAUDE.md` (rules 2, 3, 5, 7, 8, 10, 11, 14), `docs/VISION.md` §2 principles 1–3, `docs/architecture/ARCHITECTURE.md` §2 (`apps/mobile/src` layers), §5 "Daily", §6, `docs/design/DESIGN.md` §1, §3 (Title Card, Text Morph, Tray, Record), §6, DECISIONS D2, D5, D14, D32, D33.

**Stack (checked 2026-09-26 against `expo@57.0.25` `bundledNativeModules.json`, the npm registry and the installed type declarations; DECISIONS D35).** Install with `npx expo install` in `apps/mobile`: `expo-camera` (~57.0.5), `expo-audio` (~57.0.5), `expo-image-picker` (~57.0.20), `expo-location` (~57.0.20); already present: `expo-file-system`, `expo-crypto`, `expo-secure-store`, `expo-sqlite`, `expo-haptics`. Not in P5: `react-native-compressor` (Nitro-based, unverified on React Native 0.86; preview compression belongs to P6), `ffmpeg-kit-react-native` (deprecated), `expo-media-library` (not needed to read a picked file).

**API facts the tasks rely on (from the installed `.d.ts` files).**
- `expo-camera`: `<CameraView mode="video" facing mute={false} videoQuality="1080p" onCameraReady>`; `ref.recordAsync({ maxDuration: 10 })` resolves `{ uri } | undefined`; `ref.stopRecording()`; `ref.takePictureAsync()`. `mute`, `videoQuality` are view props, not record options. Start recording only after `onCameraReady`; flipping the camera mid-recording stops it. Recording with sound needs both `useCameraPermissions` and `useMicrophonePermissions`. The codec is selectable on iOS only.
- `expo-audio`: `useAudioRecorder(RecordingPresets.HIGH_QUALITY)` (AAC in `.m4a`), `prepareToRecordAsync()`, `record({ forDuration: 10 })`, `stop()`, `uri`; `setAudioModeAsync({ allowsRecording: true, playsInSilentMode: true })`; `requestRecordingPermissionsAsync()`.
- `expo-image-picker`: `launchImageLibraryAsync({ mediaTypes: ['images', 'videos'], quality: 1 })`; the asset has `uri, width, height, type, duration? (ms), fileSize?, mimeType?`. The picker does **not** trim videos (`videoMaxDuration` applies to the camera only).
- `expo-location`: `requestForegroundPermissionsAsync()`, `getCurrentPositionAsync({ accuracy: Accuracy.Balanced })`, `reverseGeocodeAsync({ latitude, longitude })` → `{ name, district, city, … }[]` on both platforms. Config plugin with `locationAlwaysAndWhenInUsePermission: false` and `locationAlwaysPermission: false`.
- Jest: jest-expo mocks module-level functions (permissions, picker, location) but not `CameraView` ref methods or `AudioRecorder` instance methods; screen tests use fake service ports instead of the modules.

**Rules for every P5 task.**
- Layers (rule 5): screens in `src/features/today/` call use cases in `src/application/` through props or a React context created in `app/`; only `src/services/` imports Expo device modules; only `src/data/` imports the SQLite driver. `app/` is the composition root that builds the real adapters.
- Time and ids come in as parameters (`now: () => Timestamp`, `newId: () => Uuid`), so use cases are testable; the real ones come from `app/` (`new Date().toISOString()` and `expo-crypto`'s `randomUUID`).
- Missing is not a value (rule 10): no mood, no place, no text unless the person gave it. A place name is stored only when the person turned it on, and coordinates are never stored.
- Words from `packages/story/src/words` (add the strings each task needs there; the words test must stay green). One amber action per screen.
- Screen tasks follow DESIGN §6: reduced motion checked, a web recording of the screen in the Design Lab job marked "not representative of 120 fps", and a device check listed as UNVERIFIED.

**Out of scope.** Uploads, sync, accounts (P4, P6), storylines and cast screens (P8; P5 only passes tag ids through), notifications (P9), the Footage archive (P10), widgets.

## T-007a · The local documentary, today's question and `captureMoment` · needs T-004d, T-005b

**Goal.** Use cases that the Today screen will call exist and are tested without a device: the app opens its store and a local documentary on first launch, gets today's question once per day, and saves a moment and its encrypted media atomically.

**Do.**
1. `src/application/ports.ts` (types only): `Clock = { now(): Timestamp; today(timeZone: string): LocalDate }`, `Ids = { newId(): Uuid }`, and a `Store` bundle type `{ driver: SqlDriver; io: FileIO; cipher: Cipher; masterKey: Uint8Array; storeDir: string }` (import the driver and port **types** only).
2. `src/application/bootstrap.ts`: `openLocalDocumentary(store, clock, ids, timeZone): Promise<Documentary>` — returns the one local documentary, creating it on first run (`title` = `words.documentary.defaultTitle`, `kind: 'solo'`, `ownerUserId` = a local user id created once and kept in the `documentaries` row; P4 links it to an account later). A second call returns the same row.
3. `src/data/repositories/moments.ts` gains `recentDaySummaries(driver, documentaryId, fromDay, toDay)` → `{ date, momentCount, placeNames, castNames }[]` (cast ids mapped to names through `cast_members`, deleted moments and cast excluded) and `placesBefore(driver, documentaryId, day)` → distinct place names of moments before `day`; `momentCountOn(driver, documentaryId, day)`. Tests on the memory driver.
4. `src/application/todayQuestion.ts`: `todayQuestion(store, documentary, clock, ids): Promise<Question>` — if a question exists for today (in the documentary's time zone) return it; otherwise build the `QuestionContext` (open storylines, the 7 days before today, places before that window, moments on `oneYearBefore(today)`, the last 60 days of questions), call `pickQuestion` with `seed = documentary.id`, store the `Question` row and return it. Two calls on the same day return the same row; the stored row parses with `Question`.
5. `src/application/captureMoment.ts`: `captureMoment(store, clock, ids, input): Promise<Moment>` where `input` is a discriminated union: `{ kind: 'answer', questionId, media: MediaInput }`, `{ kind: 'clip' | 'photo', media: MediaInput }`, `{ kind: 'note', text }`, each with optional `mood`, `placeName`, `storylineIds`, `castIds` and required `localOnly`; `MediaInput = { sourcePath, mediaKind: 'video' | 'photo' | 'audio', durationMs?, width?, height? }`. Steps:
   - media: `encryptFile` from the source into `{storeDir}/{assetId}.lde`;
   - one `transaction`: insert the `MediaAsset` (`uploadState: 'local'`), the `Moment`, mark the question answered for an answer, and insert an `UploadJob` (`pending`) **only when `localOnly` is false** (P6 replaces this check with `leavesDevice`);
   - if the transaction throws, remove the encrypted file and rethrow; if encryption throws, nothing is written;
   - after success remove the source file (it was a temporary recording or a copy).
   Every row goes through its contract before it is written (the repositories already parse).
6. `src/application/testing/`: `memoryStore()` builds a `Store` from the memory driver, `memoryFileIO`, `nodeCipher` and a fixed master key; `fixedClock(at)` and `sequentialIds()`.

**Tests** (`src/application/*.test.ts`):
- `openLocalDocumentary` creates one documentary and returns the same one on a second call.
- `todayQuestion`: first call stores and returns a question whose text matches the engine's pick for the same context; second call same day returns the same id; the next day gives a new row; an open storyline two days in a row is not asked twice (the engine's rule through the real store).
- `captureMoment`: an answer writes an encrypted file (decrypts back to the source bytes), a `MediaAsset`, a `Moment` with `questionId`, marks the question answered, and one `pending` `UploadJob`; a `localOnly` clip writes no `UploadJob`; a note writes no file and no asset; a failing transaction (force a foreign-key failure with an unknown storyline id) leaves no row and no encrypted file; the source file is removed after success and kept after a failure.
- Nothing in `src/application` imports `expo-*`, `better-sqlite3` or `expo-sqlite` (the boundary check covers it; add no new rule).

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; no screen changes in this task.

## T-007b · Device services and the composition root · needs T-007a

**Goal.** The app opens its real store at start and exposes typed capture services (camera, voice, library, place, haptics, clock, ids) to the screens through one provider, with every permission request worded from `words` and every Expo module confined to `src/services/`.

**Do.**
1. `npx expo install expo-camera expo-audio expo-image-picker expo-location`. `app.json` `plugins`: `expo-camera` (camera and microphone strings), `expo-audio` (microphone string), `expo-image-picker` (photo library string), `expo-location` (when-in-use string; `locationAlwaysAndWhenInUsePermission: false`, `locationAlwaysPermission: false`). The strings are plain and specific ("Life Documentary uses the camera to record your ten-second answers.").
2. `packages/story/src/words/permissions.ts` holds those four strings (and the in-app words for a denied permission: what it is for and how to allow it in Settings; never pushy). A test in `apps/mobile` (`app.json` read as JSON) checks that each plugin string in `app.json` equals its `words` entry, so `words` stays the one source (rule 11).
3. `src/domain/capturePorts.ts` (types only): `VideoRecorder { start(maxMs): Promise<void>; stop(): Promise<{ uri: string; durationMs: number; width: number; height: number } | null> }` (provided by a mounted camera view, see T-007c), `VoiceRecorder { start(maxMs): Promise<void>; stop(): Promise<{ uri: string; durationMs: number } | null> }`, `LibraryPicker { pick(): Promise<PickedMedia | null> }` with `PickedMedia = { uri; kind: 'video' | 'photo'; width; height; durationMs? }`, `PlaceFinder { currentPlaceName(): Promise<string | null> }` (the first non-empty of `name`, `district`, `city`; coordinates never leave the adapter), `Haptics { impactLight(): void; selection(): void }`, and `PermissionState = 'granted' | 'denied' | 'undetermined'` with a `Permissions` port (`camera`, `microphone`, `location`: `get()` and `request()`).
4. Adapters in `src/services/`: `audio/expoVoiceRecorder.ts` (expo-audio, sets the audio mode before recording, `record({ forDuration })`), `picker/expoLibraryPicker.ts`, `place/expoPlaceFinder.ts`, `haptics/expoHaptics.ts`, `permissions/expoPermissions.ts`, `clock/systemClock.ts` (`toISOString`, and the local date in a time zone with `Intl.DateTimeFormat`), `ids/expoIds.ts` (`Crypto.randomUUID()`), `camera/CameraRecorderView.tsx` — a component that renders `CameraView` in video mode, waits for `onCameraReady`, and exposes a `VideoRecorder` through a ref callback. Check each API in the installed `.d.ts`; name any gap under Risks.
5. `app/CaptureProvider.tsx` (composition root): opens the database (`openExpoDriver('life.db')`, `migrate`), loads or creates the master key, sets `storeDir` under `Paths.document`, runs `openLocalDocumentary`, and provides `{ store, clock, ids, documentary, services }` through a React context; the screen shows nothing new until it is ready, and an opening error shows a plain message from `words` (and is logged with `console.error`). `app/_layout.tsx` wraps the stack in it. Features read the context through a hook exported from `src/application/` (the context type lives there; `app/` supplies the value).
6. `src/services/testing/fakeServices.ts`: fake adapters for every port (a fake video recorder that "records" a fixture file after `stop`, a scripted picker, a fixed place name, recorded haptic calls, programmable permissions) for screen tests and the Design Lab.

**Tests.** The `app.json` ↔ `words` string test; `systemClock.today` in `Asia/Manila` and `Europe/Dublin` for a fixed instant; `expoPlaceFinder` with the mocked `expo-location` returns the first non-empty field and `null` when permission is denied; `CaptureProvider` with the memory store and fake services renders its children once ready and shows the error words when `migrate` throws (inject the opener).

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; `npx expo-doctor` no new failures; the mobile `build` (iOS export) still works; Expo device modules imported only under `src/services/` and `app/`. UNVERIFIED: permission prompts and recording on a device (P-B).

## T-007c · The Today screen and the Record transition · needs T-007b, T-003c

**Goal.** Opening the app shows today's question as a Title Card and one amber "Hold to answer" button; holding records up to 10 seconds of video (or voice, one switch away) with DESIGN §3's Record transition, and releasing saves the answer through `captureMoment`.

**Do.**
1. `src/features/today/TodayScreen.tsx` replaces `TodayPlaceholder` at `app/index.tsx`: loads `todayQuestion` on focus; shows the question with `TitleCard` variant `question` (Title Card reveal once per day, then static); the date as a `label` line; the Record button; a quiet text switch "Video · Voice" (`words`); after an answer, the saved state ("Saved" via Text Morph, the button becomes quiet) and the question stays readable.
2. `src/design-system/motion/Record.tsx` + `recordPlan.ts` (DESIGN §3 #9): on press-in the screen dims to `theatreBlack` (opacity only), the question moves to the top and shrinks (transform only) in `question` style, an amber ring (Skia, `tokens.color.accent`) fills over `maxMs` (10,000) linearly; `impactLight` haptic at start and stop; release before 1 s cancels without saving (a "hold a little longer" line from `words`, no error tone); release after 1 s or the 10 s cap stops and saves; the button label morphs "Hold to answer" → "Recording" → "Saved". `recordPlan` holds the timings as pure data: the product limits come from a new `packages/story/src/capture.ts` (`capture = { answerMinMs: 1000, answerMaxMs: 10000, libraryClipMaxMs: 60000 } as const`, exported from the package index), the motion from `tokens.motion`. Reduced motion: no transforms; the dim and the ring become a fade and a numeric countdown in `timecode` style.
3. Video mode mounts the camera view from the provider (`CameraRecorderView` on a device, the fake view in tests and the Design Lab), front camera: while holding, the live preview fills the screen under a `scrim` gradient so the question stays readable; voice mode dims to `theatreBlack` and uses `VoiceRecorder`. Permission not granted → the button asks once through `Permissions`, and a denied state shows the `words` explanation with an "Open Settings" quiet button (`Linking.openSettings()` via a `services` adapter).
4. Accessibility: the Record button is a `button` with the label from `words`; holding also works with a screen reader through a double-tap-to-start / double-tap-to-stop alternative (`accessibilityActions`); the ring's progress is announced as a value; focus order question → button → mode switch.
5. Design Lab: a "Today" section rendering `TodayScreen` with fake services and a memory store; the Playwright spec presses and holds the button for 2 s and checks "Saved" appears; the recording shows it.

**Tests** (RNTL with fake services and the memory store):
- The question from `todayQuestion` is shown; a second render the same day shows the same question.
- Holding 2 s then releasing calls `captureMoment` with an `answer`, the day's `questionId` and the recorded file, and shows "Saved"; the answer is in the store.
- Releasing after 0.5 s saves nothing and shows the hold-longer line; holding past 10 s stops at 10 s and saves.
- Voice mode records through `VoiceRecorder`.
- A denied camera permission shows the explanation and the Settings button, and no recording starts.
- `recordPlan`: min and max from tokens; reduced motion takes the fade and countdown path (no transform in the animated style).

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; CI `lab` job green with the Today section in the video (name the artifact under "UI visible"); DESIGN §6 checklist met (one amber action; nothing bounces; reduced motion checked); UNVERIFIED: recording latency, camera preview and haptics on a device.

## T-007d · Photo, library, note, mood, place and "keep on this phone" · needs T-007c

**Goal.** Below the Record button, a quiet row lets the person add a photo, pick a photo or clip from the library, write a one-line note, choose a mood, add today's place name if they allow it, and mark a capture "keep on this phone" (`localOnly`), each saved through `captureMoment`.

**Do.**
1. `src/design-system/Tray.tsx` (DESIGN §3 #6): an expo-router `formSheet` route style or a Reanimated sheet (name the choice under Decisions) with detents, moving on `spring.move`, following the finger; reduced motion: a fade. A test for the reduced path.
2. `src/features/today/extras/`: `AddRow` (four quiet icon-free text buttons from `words`: "Photo", "From library", "Note", "Place"), `NoteTray` (one `Field`, 280 characters, Save), `MoodChips` (the five `MomentMood` values with their `words` labels; optional; one tap selects, a second tap clears), `PlaceToggle` (off by default; turning it on asks for location once and shows the found name to confirm before it is used; nothing stored when off), `KeepOnPhoneToggle` (off by default, `words` explains that the moment stays on this phone and is never used in episodes).
3. Photo uses the mounted camera (`takePictureAsync`); library uses `LibraryPicker`; a picked clip longer than `capture.libraryClipMaxMs` is refused with a plain `words` line (no trimming in v1, D35); mood, place and keep-on-phone apply to the next capture and reset after it.
4. All captures call `captureMoment` with the right `kind` (`photo`, `clip`, `note`) and the chosen extras.

**Tests** (RNTL, fake services, memory store): a photo capture stores a `photo` moment with its asset; a library clip of 30 s stores a `clip`; a 61 s clip is refused and nothing is stored; a note stores a `note` with the text and no asset; a chosen mood and a confirmed place are stored on the next moment and then reset; with the place toggle off nothing is stored as a place; "keep on this phone" stores `localOnly: true` and no `UploadJob`; the Tray's reduced-motion path.

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; the Design Lab Today section shows the row and a tray opening; UNVERIFIED on a device: the photo picker's permission behaviour and a picked clip's metadata.
