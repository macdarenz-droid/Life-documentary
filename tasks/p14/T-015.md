# T-015 · P14 Narration

Text for T-015a–c. Published 2026-09-27; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P14.** After planning (P13), the pipeline turns each narrator line of a model plan (the scene bridges and the tease) into speech with ElevenLabs Flash, stores each clip in R2 with its measured length and caption cues, keeps the narrator under 25% of spoken time using the measured lengths, and leaves the episode ready to render. Placing clips and captions on the final episode timeline is P15's (the renderer owns what the episode looks like, ARCHITECTURE §6). As in P12 and P13, the vendor sits behind a port and everything is built and tested with a fixture narrator; the real calls need the owner's ElevenLabs account.

**Read first:** `CLAUDE.md` (rules 2, 3, 5, 6, 7, 9, 10, 11, 12, 14), `docs/VISION.md` line 28 and §5, `docs/architecture/ARCHITECTURE.md` §4 "Narration" and "Render", §6, §7, DECISIONS D3, D12, D20, D38, D39, D40, `tasks/p13/T-014.md` and its notes in `tasks/TASKS.md` (the plan this starts from), `tasks/p12/T-013.md` (ports, providers, the ledger).

**Decided here (DECISIONS D40).**
- **What is spoken.** Only the plan's scene bridges and its tease, in plan order (`narrationLines`). A recap plan has none and skips this step. The person's answers are never synthesised or re-voiced (D3, D12; no cloning).
- **The cast.** Our ids `narrator-1` … `narrator-4` map to four ElevenLabs voice ids in the Worker variable `NARRATOR_VOICES` (a JSON object), set by the owner after choosing and listening, never in code. ElevenLabs' Default voices expire on 31 December 2026, so the owner picks from voices that stay available (the named replacement voices or voices the account owns). Choosing a narrator per person is later work; every plan uses the voice `assemblePlan` set (`narrator-1`).
- **The request.** `POST https://api.elevenlabs.io/v1/text-to-speech/{voiceId}/with-timestamps?output_format=mp3_44100_128`, header `xi-api-key`, body `{ text, model_id: 'eleven_flash_v2_5', language_code: 'en' }`, voice settings left at their defaults. Raw `fetch` from the provider, no SDK (the SDK brings Node-only dependencies). Responses are parsed leniently (unknown fields ignored, as ElevenLabs' API terms require), and errors are handled by HTTP status.
- **Length and cues come from the alignment.** The response's `alignment` (characters with start and end seconds) gives each clip's length (the last character's end) and its caption cues: chunks of at most 120 characters broken at word ends, each from its first character's start to its last character's end. A line whose response has no alignment, or that still fails after the step's retry, is left out (missing stays missing, rule 10); the rest of the episode goes on.
- **The 25% cap on real audio.** After synthesis, `fitNarration` measures the narrator's share with the real clip lengths against the person's spoken time (the cold open and the answer shots, by `shotMs`). While the share is above 25%, it drops the tease first, then bridges from the last scene backwards. Dropped lines keep their stored clips (a later edit may use them) but are marked not kept.
- **Cache.** A clip is keyed by a SHA-256 of (vendor voice id, model id, output format, text). A retry, a re-run or a later plan version reuses a stored clip with the same key instead of paying again. Audio is never regenerated expecting the same bytes (ElevenLabs does not promise determinism).
- **Storage.** Clips live at `u/{userId}/{documentaryId}/narration/{episodeId}/{hash}.mp3` (under `u/`, so the `tmp/` lifecycle rule never touches them; deleted with the account in P21). Rows in D1 `narration_clips`: episode, plan version, line index, line kind (`bridge` or `tease`), scene index, text, our voice id, key, hash, length, cues, kept, created at.
- **Answer captions need timings, so P12 keeps them.** Whisper's segments are stored with the transcript (P12 fix lists); the phone does not store them. `answerCues` uses them relative to the answer's start; an answer without segments gets its transcript in chunks of at most 120 characters spread evenly over its length (the words are real, only their timing is approximate).
- **Numbers.** Flash reads digits badly and ElevenLabs only normalises text on Enterprise plans, so the planner writes numbers, dates and times in words (a note on T-014b). `speakable(text)` refuses a line that still has a digit (logged, left out like a failed line).
- **Costs.** One ledger row per episode for step `narrate`, provider `elevenlabs`, unit `character` (the characters sent, as the `character-cost` response header reports, or the text length when it is missing), at 50 µUSD per character ($0.05 per 1,000). A reused clip costs nothing.
- **Privacy.** The owner turns off "Improve the models for everyone" in the ElevenLabs account (inputs are used for training by default below Enterprise). Bridge text holds no user words (P13's copy check), so no transcript text reaches ElevenLabs.

**Stack (checked 2026-09-27).**
- ElevenLabs: `eleven_flash_v2_5` (32 languages, 40,000 characters per request, about 75 ms); with-timestamps returns `{ audio_base64, alignment: { characters, character_start_times_seconds, character_end_times_seconds } | null, normalized_alignment: same | null }`; response headers `request-id` and `character-cost`; errors 400/401/402/403/404/409/422/429/5xx (429 when a concurrency limit is reached: back off, never retry at once); `output_format` is a query parameter; `enable_logging=false` (zero retention) is Enterprise only. Whether Flash returns an alignment on with-timestamps is not documented: the owner's first real call checks it.
- The Workers test pool and Workflows as in P12/P13 (`remoteBindings: false`; `retries` needs `limit` and `delay`; `dispose()` introspectors in `finally`). The fixture narrator returns a small valid MP3 from a test fixture and a synthetic alignment.
- `crypto.subtle.digest('SHA-256', …)` is available in Workers for the cache key.

**Rules for every P14 task.** Only plan text written by the planner (bridges and the tease, already checked by P13 for the voice rules and for copying the person's words) is ever sent to ElevenLabs; a test proves no transcript, note or caption text appears in a narrator request. Missing stays missing: a line with no audio or no alignment is left out, never replaced. The provider holds no product policy: the model id, the format, the cast mapping, the cap, the cache and the order of dropping live in `pipeline/`, `policy/` and `packages/story`. No test calls ElevenLabs or logs a key. Names avoid the banned-identifier list (for example no `speakerId`).

**Out of scope.** Placing clips and captions on the episode timeline and the caption track (P15), choosing a narrator per person, voice cloning (never in release 1), streaming speech, request stitching, pronunciation dictionaries, other languages.

## T-015a · Narration shapes and rules · needs T-014a

**Goal.** The pure parts of narration exist and are tested: which lines are spoken, when a line may be spoken, how cues come from an alignment or a transcript, and how the 25% cap is kept with measured lengths.

**Do.**
1. `packages/contracts/src/episode/narration.ts`: `NarrationLine { index, kind: 'bridge' | 'tease', sceneIndex?, text }`; `CaptionCue { fromMs: int ≥ 0, toMs: int, text 1..120 }` (`toMs` > `fromMs`); `NarrationClip { episodeId, planVersion, index, kind, sceneIndex?, text, voiceId, key, hash, durationMs: int ≥ 1, cues: CaptionCue[] (1..20), kept: boolean, createdAt }`. `CostLedgerRow` gains step `narrate`, provider `elevenlabs`, unit `character`.
2. `narrationLines(plan)` → the bridges in scene order, then the tease, indexed from 0; none for a plan without narration.
3. `speakable(text)` → `true` unless the text has a digit or is empty after trimming.
4. `lineCues(text, alignment)` → cues from a character alignment (`characters`, `startSeconds`, `endSeconds`, equal lengths): chunks of at most 120 characters broken after a space, each timed from its first non-space character's start to its last character's end, in whole milliseconds; `null` when the alignment is missing, empty, of unequal lengths or does not spell the text.
5. `answerCues(transcript, segments, durationMs)` → with segments: one cue per segment (text trimmed, at most 120 characters, a longer segment split at word ends with its time shared in proportion to characters), clamped to the answer's length and dropping empty ones; without segments: the transcript in chunks of at most 120 characters at word ends, spread evenly over `durationMs`.
6. `fitNarration(lines, clipMs, plan, brief)` → the indices to keep: the person's spoken time is the cold open's span plus the answer shots' `shotMs`; while (Σ kept clip ms) × 4 > (Σ kept clip ms + person's spoken time), drop the tease first, then bridges from the last scene backwards.

**Tests.** `narrationLines` on a plan with three bridges and a tease; `speakable` refuses "Week 12" and passes "Twelve weeks in"; `lineCues` on a hand-made alignment of a 150-character line gives two cues broken at a space with the right times, and `null` for a mismatched alignment; `answerCues` with two segments, with one long segment, and with none (even spread whose last cue ends at the answer's length); `fitNarration` keeps everything under the cap, drops the tease first, then the last scene's bridge, and keeps nothing when the person never speaks; `NarrationClip` refuses a 121-character cue and a cue that ends before it starts.

**Acceptance.** Contracts and story typecheck, tests, lint, format, boundaries pass; `packages/story` still imports only `@life/contracts` and `zod`.

## T-015b · The ElevenLabs provider · needs T-013c, T-015a

**Goal.** The pipeline can turn a line into speech through a port, with real and fixture adapters, and no test can reach ElevenLabs.

**Do.**
1. `Narrator` in `ports.ts`: `speak({ voiceId, text, modelId, outputFormat, languageCode }) → { audio: Uint8Array, alignment: { characters: string[], startSeconds: number[], endSeconds: number[] } | null, characters: number }`.
2. `providers/elevenlabs/narrator.ts`: the request from "Decided here" with the values it is given; decodes `audio_base64`; maps `alignment` (not `normalized_alignment`) or `null`; `characters` from the `character-cost` header, else the text length; parses the body with a non-strict schema; throws on a non-2xx status with the status in the message and never the key or the text. Without `ELEVENLABS_API_KEY` its first call throws `Narration is not set up`.
3. `providers/fixture/narrator.ts`: records calls and returns a small valid MP3 (a checked-in fixture file) with an alignment spelling the text (a fixed 60 ms per character), or what a test sets (no alignment, an error).
4. `pipelineProviders(env)` also returns the narrator (fixture only with `PROVIDERS: 'fixture'`). `Env` gains `ELEVENLABS_API_KEY?` and `NARRATOR_VOICES?`.
5. `pipeline/narrate/settings.ts`: `NARRATE_MODEL = 'eleven_flash_v2_5'`, `NARRATE_FORMAT = 'mp3_44100_128'`, `NARRATE_LANGUAGE = 'en'`; `vendorVoice(env, ourId)` parses `NARRATOR_VOICES` (a JSON object of `narrator-1`…`narrator-4` to non-empty strings) and throws `The narrator voices are not set up` when it is missing, not JSON, or lacks the id.
6. `narrateMicroUsd(characters)` in `policy/costs.ts` = 50 × characters.

**Tests.** The adapter against a stubbed `fetch`: the URL with the voice id and `output_format` query, the `xi-api-key` header, the body with text, model id and language code; it maps the alignment, returns `null` alignment when the response has none, reads `character-cost`, ignores unknown response fields, and throws on 429 with the status and without the text or key in the message; without a key it throws `Narration is not set up`; `vendorVoice` for a good map, a missing variable, bad JSON and a missing id; `narrateMicroUsd(140)` is 7,000; the boundary check passes (no vendor SDK).

**Acceptance.** API typecheck, tests, lint, format, boundaries, `deploy:dry` pass. UNVERIFIED until the owner's account: a real call, whether Flash returns an alignment, the chosen voices.

## T-015c · EpisodePipeline step 3: narrate · needs T-014c, T-015a, T-015b

**Goal.** An episode whose plan has narration gets a clip for each line it can speak, the cap is kept on real lengths, the clips and their cues are stored, the cost is recorded, and the episode moves on to rendering.

**Do.**
1. The next D1 migration: `narration_clips` (the `NarrationClip` fields, `cues` as JSON text; `episode_id` references `episodes` with ON DELETE CASCADE; unique `(episode_id, plan_version, index)`), with its migration test. `data/repositories/narration.ts`: `put`, `forEpisode(episodeId, planVersion)`, `byHash(episodeId, hash)`, `setKept(episodeId, planVersion, indices)`. `mediaKeys.ts` gains `narrationKey(userId, documentaryId, episodeId, hash)`.
2. `pipeline/narrate/*.ts`, plain functions over `{ db, media, narrator, env, clock }`: `lineStep(episode, plan, line)`: when `speakable` refuses it, return `{ outcome: 'skipped' }`; the hash; a stored clip with that hash for this episode is copied to this plan version's row and reused (`{ outcome: 'reused' }`); otherwise `speak`, `lineCues` (a `null` result means `{ outcome: 'no-alignment' }` and nothing stored), put the MP3 in R2 (content type `audio/mpeg`) at `narrationKey`, store the row with `durationMs` = the last character's end and `kept: true`; return `{ outcome: 'spoken', characters }`. `fitStep(episode, plan)`: `fitNarration` over the stored clips of this plan version; `setKept`; state `rendering`.
3. `EpisodePipeline.ts`, after the plan steps: when the episode's state is `narrating`, one `narrate-{index}` step per line (`retries: { limit: 1, delay: '30 seconds' }`; `run` catches a step that still fails and goes on without that line), then `narrate-fit`, then `narrate-costs` (one ledger upsert for `narrate` / `character` over the characters the steps returned, by `narrateMicroUsd`, then `costCents`). Step results carry outcomes and counts only, never audio or text.

**Tests** (Workers pool, D1 and R2 in Miniflare, the fixture narrator). A plan with three bridges and a tease stores four clips with their cues and lengths, puts four MP3s in R2 under `u/…/narration/`, and ends in `rendering`; a second run reuses every clip (no narrator call) and adds no cost; a line with a digit is skipped without a call; a line whose response has no alignment is left out and the others kept; a narrator that fails every attempt for one line leaves that line out and the run completes; a plan whose measured narration is over 25% ends with the tease and then the last bridge not kept; a recap plan has no narrate steps; no narrator request carries a transcript, a note or a caption from the week (seeded in D1); the ledger row counts the characters of spoken lines only.
Allowed test changes: T-014c's Workflow tests that expect the run to end in `narrating` now expect `rendering`.

**Acceptance.** API, contracts and story typecheck, tests, lint, format, boundaries, `deploy:dry` pass. UNVERIFIED until the owner's account: real speech for a real plan.
