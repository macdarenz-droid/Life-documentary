# T-009 · P10 Footage (the local archive)

Text for T-009a–d. Published 2026-09-26; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P10.** The person can look back. A Footage screen shows every moment by day, newest first, and by storyline; a moment opens full screen and plays; the person can fix its note, mood and tags or delete it; and Today shows "One year ago today" when there is something from that day. Everything is local: nothing leaves the device (P6 adds upload and sync). This moves "the Footage screen lists moments by day and plays them" from P6 to here, because it needs no server (ROADMAP is updated with this text).

**Read first:** `CLAUDE.md` (rules 2, 5, 6, 7, 8, 10, 11, 14), `docs/VISION.md` §2 and §8, `docs/architecture/ARCHITECTURE.md` §2 (`apps/mobile/src` layers), §3 (`Moment`, `MediaAsset`), §6, `docs/design/DESIGN.md` §1, §3 (#4 Dissolve, #5 Filmstrip, #6 Tray), §6, DECISIONS D33, `tasks/p5/T-007.md` preamble (layers, ports, words, screen recordings), `tasks/p8/T-008.md` "Navigation".

**Stack (checked 2026-09-26 against `expo@57.0.25` `bundledNativeModules.json` and the packages' `.d.ts` files).** Install with `npx expo install` in `apps/mobile`:
- `expo-video-thumbnails` (~57.0.2): `getThumbnailAsync(uri, { time /* ms */, quality /* 0–1 */ })` → `{ uri, width, height }` (a JPEG file). No web implementation (it rejects), so tests and the Design Lab use a fake.
- `expo-image-manipulator` (~57.0.20): `ImageManipulator.manipulate(uri).resize({ width })` (or `{ height }`; the other side keeps the ratio) → `.renderAsync()` → `ImageRef.saveAsync({ compress, format: SaveFormat.JPEG })` → `{ uri, width, height }`. `manipulateAsync` is deprecated; do not use it.
- `@shopify/flash-list` (2.0.2) for the Filmstrip and the day list.
- Already present: `expo-video` (`useVideoPlayer(source)`, `<VideoView player nativeControls={false}>`), `expo-audio` (`useAudioPlayer(source)`), `expo-image`, `expo-file-system`.

**Decided here.**
- **Posters.** Photos and videos get a small poster (longest side 480 px, JPEG, `compress` 0.7; a video's frame at 500 ms, or at 0 ms when it is shorter), encrypted into the file store like every original (D33). Voice answers and notes have no poster; their rows show the question or the note in type. A poster that cannot be made is simply absent: the row shows a plain `surface` frame (rule 10).
- **Playback copies.** A player needs a plain file, so opening a moment decrypts its original to the app's cache (`playback/`), and a poster to `posters/`, both cleared at every app start; a playback copy is also removed when the viewer closes. The file's container is read from its first bytes (a pure function), because the store keeps no extension: `ftyp` with major brand `qt  ` → `.mov`, `M4A ` → `.m4a`, `heic`/`heix`/`mif1`/`msf1` → `.heic`, any other `ftyp` → `.mp4`; `FF D8 FF` → `.jpg`; `89 50 4E 47` → `.png`; anything else → it cannot be opened (a `words` line, never a guess).
- **Captions.** Until transcripts exist (P12), the viewer shows the question (for an answer) and the note as caption text over a `scrim`; no transcript is invented.
- **Delete** is a tombstone (`deletedAt`) plus removal of the encrypted original, its poster and any upload job; the media asset row stays because the tombstone points at it (sync needs the tombstone in P6). Deleting today's answer makes today's question answerable again.

## T-009a · Posters and playback copies · needs T-008c

**Goal.** Every new photo or video moment gets an encrypted poster; any stored original or poster can be turned into a temporary plain file of the right type for a player; the integrity check knows about posters.

**Do.**
1. `MediaAsset` gains `posterPath` and `posterWrappedKey`, both optional and present together (a `superRefine` issue otherwise); `DOMAIN_SCHEMA_VERSION` goes up by one; the next append-only device migration after the last one on the base adds the two nullable columns to `media_assets`, with its migration test from a seeded database at the previous version (rule 6); the repository reads and writes them.
2. `src/data/fileStore/container.ts`: `containerOf(head: Uint8Array): 'mov' | 'mp4' | 'm4a' | 'heic' | 'jpg' | 'png' | null` by the table above (at least 12 bytes read; fewer → `null`).
3. `FileIO` gains `move(from, to)`: the Expo adapter uses `expo-file-system`'s `File.move(destination)` (a promise in SDK 57), the Node test adapter `fs.rename`.
4. `src/domain/capturePorts.ts`: `PosterMaker { fromVideo(uri, atMs): Promise<{ uri; width; height } | null>; fromPhoto(uri, maxSide): Promise<{ uri; width; height } | null> }`; adapter `src/services/posters/expoPosterMaker.ts` (thumbnail, then resize to 480 on the longest side for both; any error → `null`); fake in `src/services/testing/fakeServices.ts` that writes fixture bytes. The context's `CaptureServices` gains `posters`.
5. `src/application/posters.ts`: `ensurePoster(store, posters, assetId)`: nothing for audio or when a poster exists; otherwise decrypt the original to the cache, make the poster, encrypt it to `<storeDir>/<assetId>.poster.lde`, store the path and wrapped key on the asset, and remove both plain files (also when anything fails; a failure leaves the asset without a poster and returns `false`). `TodayRoute`'s `save` calls it after every `captureMoment` that stored media; the capture never fails because of a poster.
6. `src/application/playback.ts`: `openOriginal(store, assetId)` and `openPoster(store, assetId)` decrypt to `<cacheDir>/playback/<assetId>.<ext>` and `<cacheDir>/posters/<assetId>.<ext>` (decrypt to a `.part` name, read the head, `move` to the final name; an unknown container removes the file and gives `null`); `openPoster` reuses an existing copy; `closeOriginal(store, assetId)` removes the playback copy; `clearPlaybackCache(store)` empties both folders and runs in `CaptureRoot` after the store opens. `Store` gains `cacheDir` (the composition root passes the app cache; tests a temp folder).
7. `src/data/integrity.ts`: a poster file is not an orphan; a missing poster or original of an asset whose moments are all deleted is not a problem.

**Tests.** The migration keeps every row and adds the columns; `MediaAsset` refuses a poster path without its key; `containerOf` for each brand and signature, a 5-byte head and an unknown one; `ensurePoster` on the memory store makes an encrypted poster for a video and a photo (the stored file is not the plain bytes; opening it gives them back), does nothing for audio, and leaves no plain file behind when the poster maker returns `null` or throws; after a video capture through `TodayRoute`'s `save` the asset has a poster; `openOriginal` gives a `.mov` for a QuickTime fixture and `null` plus no file for random bytes; `clearPlaybackCache` empties the folders; the integrity check stays clean with posters and after a moment's files are removed with the moment deleted.

**Acceptance.** Mobile and contracts typecheck, tests, lint, format, boundaries pass; `npx expo-doctor` no new failures; UNVERIFIED: poster generation and `File.move` on a device.

## T-009b · Footage use cases · needs T-009a, T-008a

**Goal.** Pure-enough use cases give the screens everything they show about past moments, and the edits and delete, tested on the memory store.

**Do.**
1. `packages/story/src/footage.ts` (exported from the index): `timeLabel(capturedAt, timeZone)` → `"09:41"` (24-hour, the moment's own zone); `durationLabel(ms)` → `"0:09"` / `"1:00"` (whole seconds, rounded down, never below `0:01` for a positive duration).
2. `src/application/footage.ts`:
   - `footageDays(store, documentary, { beforeDay?, days })` → up to `days` distinct local days that have non-deleted moments, newest first, strictly before `beforeDay` when given, each `{ date, dayLabel, items }` with items by capture time.
   - A `FootageItem` holds only what the screens show: `id, kind, mediaKind?, timeLabel, durationLabel?, questionText?, text?, mood?, placeName?, storylineIds, castIds, localOnly, hasPoster, assetId?`.
   - `footageByStoryline(store, documentary, storylineId)` → that storyline's items, newest first; `footageStorylines(store, documentary)` → open then closed storylines that have at least one moment, with their counts.
   - `oneYearAgo(store, documentary, today)` → the items on `oneYearBefore(today)`, oldest first.
   - `editMoment(store, clock, id, { text?: string | null; mood?: MomentMood | null })`: `text` trimmed with the same limit the Note tray uses (280); `null` removes it; a note moment keeps a text (removing it is a `words` error); bumps `updatedAt`. Tags go through `tagMoment` (T-008a).
   - `deleteMoment(store, clock, id)`: in one transaction, the tombstone and the removal of its upload job and, when the moment answered a question, that question's `answeredByMomentId`; then the encrypted original and poster files are removed. Idempotent for an already deleted moment.
3. The queries these need live in the repositories (`moments`: days before a day, by storyline; `uploadJobs`: `remove`; `questions`: clear the answer), each with a repository test.

**Tests.** `timeLabel` across a time-zone change (the same instant in two zones) and `durationLabel` edges; `footageDays` paging over 20 seeded days with a gap, deleted moments left out, a day with only deleted moments left out; `footageByStoryline` order; `oneYearAgo` on 2028-02-29 reads 2027-02-28; `editMoment` trims, removes a mood, refuses a 281-character text and an empty text on a note; `deleteMoment` leaves a tombstone, no upload job, no files, and today's question answerable again (through `todayQuestion`), and a second call changes nothing.

**Acceptance.** Mobile and story typecheck, tests, lint, format, boundaries pass.
