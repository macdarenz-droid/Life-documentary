# T-004 · P3 Local store

Text for T-004a–d. Published 2026-09-26; this file does not change after publication. Fix lists are written in `tasks/TASKS.md` under the task.

## Preamble

**Goal of P3.** The device keeps every moment, question, storyline, cast member, episode view and upload job in SQLite with an append-only, tested migration history, behind repositories in `apps/mobile/src/data`; originals are encrypted at rest with per-file keys wrapped by a master key held in the platform keychain. Every stored row is a Zod contract in `packages/contracts` and is parsed when read.

**Read first:** `CLAUDE.md` (rules 3, 5, 6, 7, 10), `docs/architecture/ARCHITECTURE.md` §2 (`data/` row), §3, §6, §7, DECISIONS D5, D14, D25.

**Stack (checked 2026-09-26 against `expo@57.0.25` `bundledNativeModules.json`, the npm registry and the installed packages; DECISIONS D32, D33).**
- Runtime, installed with `npx expo install` in `apps/mobile`: `expo-sqlite` (~57.0.3), `expo-file-system` (~57.0.7, the `File`/`Directory`/`FileHandle` API, not `/legacy`), `expo-crypto` (~57.0.3, AES-256-GCM via `AESEncryptionKey` and `aesEncryptAsync`/`aesDecryptAsync`), `expo-secure-store` (~57.0.4). Pure JS: `@noble/hashes` (^2.4.0, incremental `sha256` from `@noble/hashes/sha2.js`).
- Dev only, for Node-side tests of `data/`: `better-sqlite3` (~13.0.3, prebuilt binaries for Node 22, no install script) and `@types/better-sqlite3` (~9.6.0).
- No ORM on the device (D32): hand-written, append-only SQL migrations behind a small `SqlDriver` port, repositories that parse every row with its contract. No SQLCipher in v1 (D33).

`app/` wires the real adapters later (P5); nothing in this phase opens the real database at app start.

**Traps (read before building).**
- `PRAGMA foreign_keys = ON` is set on every open, outside any transaction (it does nothing inside one), in both adapters. `better-sqlite3` defaults it on and the device build defaults it off, so tests would hide a missing pragma: the adapter test checks it explicitly.
- `PRAGMA user_version = ?` cannot take a bound parameter; write the integer literal.
- expo-sqlite's `withTransactionAsync` is not exclusive; use `withExclusiveTransactionAsync` and run every statement through its `txn` object.
- jest-expo cannot open a real expo-sqlite database (the native class is not mocked), and expo-crypto's Jest mocks are empty: every behaviour test runs on the Node adapters; the Expo adapters are thin and are verified on a device in P-B (UNVERIFIED until then).
- `tooling/dependency-cruiser.cjs` rule `sqlite-only-in-data` allows `expo-sqlite` and `better-sqlite3` only under `apps/mobile/src/data/`, so the test adapters live there.
- iOS keeps Keychain items after an uninstall, Android does not: the integrity check reports "files but no master key" and "master key but no database" instead of crashing.

**Rules for every P3 task.** Every row written is parsed with its contract first, and every row read is parsed before it is returned; a row that fails is an error (`CorruptRowError` with table and id), never silently skipped. Time comes in as a parameter (`now: Timestamp`); no `Date.now()` inside `data/`. Randomness comes only from the `Cipher` port.

**Out of scope.** Capture screens and `captureMoment` (P5), the upload network protocol and sync (P6), wiring the question engine to storage (P8/P9), D1 on the server (P4/P6).

## T-004a · Domain contracts v1 · needs T-005a

**Goal.** Every entity the device stores is a versioned contract in `packages/contracts` with its cross-field rules, so repositories, sync and the story engine share one shape.

**Do.** In `packages/contracts/src/domain/`, exported from the package index (names exactly as below, types inferred with the same names):
1. `Timestamp = z.iso.datetime()` (UTC, ending in `Z`) in `packages/contracts/src/ids.ts` beside `LocalDate`.
2. `Documentary`: `id: Uuid`, `ownerUserId: Uuid`, `title` 1–80, `kind: z.enum(['solo', 'shared'])`, `timeZone: IanaTimeZone`, `episodeDay` int 0–6 (0 = Sunday, default 0), `episodeHour` int 0–23 (default 18), `createdAt`, `updatedAt: Timestamp`.
3. `MomentKind = z.enum(['answer', 'clip', 'photo', 'note'])`; `MomentMood = z.enum(['bright', 'calm', 'tender', 'tired', 'heavy'])` (chosen by the user, never inferred); `Moment`: `id`, `documentaryId`, `authorUserId: Uuid`, `capturedAt: Timestamp`, `timeZone: IanaTimeZone`, `kind`, `questionId?: Uuid`, `mediaAssetId?: Uuid`, `text?` 1–500, `mood?`, `placeName?` 1–80, `localOnly: boolean`, `storylineIds: Uuid[]` (max 10, unique), `castIds: Uuid[]` (max 20, unique), `updatedAt: Timestamp`, `deletedAt?: Timestamp`. Refinements: `answer` needs `questionId` and `mediaAssetId`; `clip` and `photo` need `mediaAssetId`; `note` needs `text` and has no `mediaAssetId`.
4. `MediaAsset`: `id`, `ownerUserId: Uuid`, `kind: z.enum(['video', 'photo', 'audio'])`, `durationMs?` int ≥ 1, `width?`, `height?` int ≥ 1, `bytes` int ≥ 1, `sha256` (64 lowercase hex), `localPath` min 1, `wrappedKey` min 1 (base64), `cloudKey?` min 1, `uploadState: z.enum(['local', 'queued', 'uploading', 'uploaded'])`, `createdAt: Timestamp`. Refinements: `video` and `audio` need `durationMs`; `video` and `photo` need `width` and `height`.
5. `Question` (the stored row): `id`, `documentaryId: Uuid`, `templateId` (`/^q\d{3}$/`), `reason: QuestionTag`, `askedOn: LocalDate`, `storylineId?: Uuid`, `text` 12–200, `answeredByMomentId?: Uuid`.
6. `Storyline`: `id`, `documentaryId`, `title` 1–60, `openedAt`, `closedAt?`, `summary?` ≤ 400, `updatedAt`, `deletedAt?`; refinement `closedAt > openedAt` when present. `CastMember`: `id`, `documentaryId`, `name` 1–40, `relation?` 1–40, `createdAt`, `updatedAt`, `deletedAt?`. No photo, face or voice field of any kind (rule 7).
7. `EpisodeState = z.enum(['scheduled', 'understanding', 'planning', 'narrating', 'rendering', 'ready', 'failed', 'recap'])`; `Episode`: `id`, `documentaryId`, `number` int ≥ 1, `weekStart`, `weekEnd: LocalDate` (refined: `weekStart` + 6 days), `state`, `planVersion` int ≥ 0, `renderVersion` int ≥ 0, `mp4Key?`, `posterKey?`, `durationMs?` int ≥ 1, `costCents` int ≥ 0, `summary?` ≤ 400, `deliveredAt?: Timestamp`, `updatedAt: Timestamp`.
8. `UploadJob`: `assetId: Uuid`, `state: z.enum(['pending', 'uploading', 'completing', 'done', 'failed'])`, `uploadId?` min 1, `parts: { partNumber: int ≥ 1, etag: string min 1 }[]` (part numbers unique), `bytesDone` int ≥ 0, `attempts` int ≥ 0, `nextAttemptAt?: Timestamp`, `updatedAt: Timestamp`.
9. `DOMAIN_SCHEMA_VERSION = 1 as const`.

**Tests** (`packages/contracts/test/domain.test.ts`): one valid fixture per schema parses; rejections, one per case: an `answer` without `questionId`; a `note` with a `mediaAssetId`; a `clip` without media; 11 storyline ids and a duplicated cast id; a `video` without `durationMs`; a `sha256` of 63 characters or uppercase hex; a `Question` with an unknown `reason`; a `Storyline` closed before it opened; an `Episode` whose `weekEnd` is not `weekStart` + 6; an `UploadJob` with duplicate part numbers; a `Timestamp` with an offset (`+01:00`) or without a time.

**Acceptance.** Contracts tests, typecheck, lint, format, boundaries pass; `packages/contracts` still depends only on `zod`.

## T-004b · SQLite driver port, schema v1 and the migration harness · needs T-004a

**Goal.** A database opened through one small port gets schema v1 from an append-only migration list; migrations are exclusive, all-or-nothing, refuse downgrades and detect an edited past migration, and all of it is tested in Jest on the Node adapter.

**Do.**
1. `npx expo install expo-sqlite`; add `better-sqlite3` and `@types/better-sqlite3` as devDependencies of `@life/mobile` (versions in the preamble).
2. `src/data/sqlite/driver.ts`: `type SqlValue = string | number | null`; `interface SqlDriver { exec(sql: string): Promise<void>; run(sql: string, params?: SqlValue[]): Promise<{ changes: number }>; all<T>(sql: string, params?: SqlValue[]): Promise<T[]>; first<T>(sql: string, params?: SqlValue[]): Promise<T | undefined>; transaction<T>(fn: (tx: SqlDriver) => Promise<T>): Promise<T>; close(): Promise<void> }`. `transaction` is exclusive; a throw inside rolls everything back and rethrows.
3. `src/data/sqlite/expoDriver.ts`: `openExpoDriver(name: string): Promise<SqlDriver>` over `openDatabaseAsync`; `transaction` uses `withExclusiveTransactionAsync` and hands `fn` a driver bound to its `txn` (calling `transaction` on that bound driver runs inside the current transaction); on open, outside any transaction: `PRAGMA foreign_keys = ON`, `PRAGMA journal_mode = WAL`.
4. `src/data/sqlite/testing/memoryDriver.ts`: `openMemoryDriver(): Promise<SqlDriver>` over `better-sqlite3` `':memory:'` with the same pragmas; `transaction` with `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`; nested `transaction` calls on the `tx` object run inside the outer one (no new BEGIN).
5. `src/data/migrations/v1.ts` and `index.ts`: `export const migrations: readonly Migration[]` with `Migration = { version: number; name: string; sql: string }`. v1 (`name: 'initial'`) creates, in `snake_case` with columns matching T-004a's contracts: `documentaries`, `moments`, `moment_storylines (moment_id, storyline_id)`, `moment_cast (moment_id, cast_id)`, `media_assets`, `questions`, `storylines`, `cast_members`, `episodes`, `upload_jobs`, `upload_job_parts (asset_id, part_number, etag)`. Also a `local_day TEXT NOT NULL` column on `moments` (the capture day in the moment's time zone, written by the repository in T-004c). Timestamps and dates are `TEXT`, booleans `INTEGER` 0/1, enums have `CHECK (… IN (…))`, foreign keys with `ON DELETE CASCADE` only for the join and part tables. Indexes: `moments (documentary_id, local_day)`, unique `questions (documentary_id, asked_on)`, `upload_jobs (state, next_attempt_at)`.
6. `src/data/migrations/migrate.ts`: `migrate(driver, list = migrations): Promise<{ from: number; to: number }>`:
   - validates the list first (versions 1, 2, 3… contiguous, names non-empty) and throws `MigrationListError` without touching the database;
   - keeps `schema_migrations (version INTEGER PRIMARY KEY, name TEXT, checksum TEXT, applied_at TEXT)` (created by the harness itself, before v1) and `PRAGMA user_version` equal to the highest applied version;
   - throws `MigrationEditedError` when an applied version's checksum (sha256 hex of its `sql`, via `@noble/hashes`) differs from the list;
   - throws `DowngradeError` when the database is at a version above the list's last;
   - applies each pending migration in its own `transaction`: its `sql`, the `schema_migrations` row, and `PRAGMA user_version = <literal>`.
   `applied_at` comes from a `now: Timestamp` argument.
7. `src/data/migrations/testing/seedV1.ts`: a helper that migrates a memory database to v1 and inserts one row per table, for the next schema version's migration test (rule 6).

**Tests** (`src/data/migrations/migrate.test.ts`, `src/data/sqlite/memoryDriver.test.ts`):
- The memory driver: `PRAGMA foreign_keys` reads 1; a throw inside `transaction` leaves no row behind; a nested `transaction` on `tx` commits with the outer one.
- A fresh database migrates `{ from: 0, to: 1 }`; every table and index of v1 exists (`sqlite_master`); `user_version` is 1; a second run returns `{ from: 1, to: 1 }` and changes nothing.
- A list with a v2 whose SQL fails midway leaves the database at v1 with no v2 table and no `schema_migrations` row for v2.
- Editing v1's SQL after it was applied → `MigrationEditedError`; a database at v3 with a two-item list → `DowngradeError`; a list `[1, 3]` → `MigrationListError` and the database is untouched.
- `seedV1` inserts a row in every table without a foreign-key error.
- A CHECK constraint rejects an unknown `moments.kind`.

**Acceptance.** Mobile typecheck, tests, lint, format and `pnpm boundaries` pass; `npx expo-doctor` has no new failures; `expo-sqlite` and `better-sqlite3` are imported only under `src/data/`.

## T-004c · Repositories and the integrity check · needs T-004b, T-006b

**Goal.** Each stored entity has a repository over `SqlDriver` that writes and reads only contract-valid rows, with the queries the next phases need, plus a database integrity check.

**Do.**
1. `src/data/repositories/` — one module per entity, each a set of functions taking a `SqlDriver` (so they run inside a caller's `transaction` too):
   - `documentaries`: `put`, `get`.
   - `moments`: `put(driver, moment)` (upsert; writes `local_day = localDay(capturedAt, timeZone)` from `@life/story` and replaces its `moment_storylines` / `moment_cast` rows in the same transaction), `get`, `listByDays(driver, documentaryId, fromDay, toDay)` (inclusive, by `local_day`, ordered by `captured_at` then `id`, deleted excluded unless `{ includeDeleted: true }`), `softDelete(driver, id, now)` (sets `deletedAt` and `updatedAt`).
   - `mediaAssets`: `put`, `get`, `listAll` (for the integrity check).
   - `questions`: `put` (the unique day index makes a second question for the same day a `ConflictError`), `getForDay`, `listSince(driver, documentaryId, fromDay)` (the engine's `history`), `markAnswered(driver, id, momentId)`.
   - `storylines`: `put`, `get`, `listOpen(driver, documentaryId)` (no `closedAt`, not deleted, by `openedAt`).
   - `castMembers`: `put`, `get`, `list(driver, documentaryId)` (not deleted, by name).
   - `episodes`: `put`, `get`, `listRecent(driver, documentaryId, limit)` (by `number` descending) — the device's episode view.
   - `uploadJobs`: `put` (writes its parts), `get`, `listDue(driver, now, limit)` (`state` `pending` or `failed` with `next_attempt_at` null or ≤ `now`, oldest first).
   Every `put` parses its input with the contract; every read maps `snake_case` columns back and parses with the contract; a failing row throws `CorruptRowError { table, id }`.
2. `src/data/integrity.ts`: `checkDatabase(driver): Promise<IntegrityReport>` with `IntegrityReport = { ok: boolean; problems: { kind: 'sqlite' | 'foreignKey' | 'corruptRow'; table?: string; id?: string; detail: string }[] }` from `PRAGMA integrity_check`, `PRAGMA foreign_key_check`, and a parse of every row of every table (a `CorruptRowError` becomes a problem instead of a throw here).

**Tests** (`src/data/repositories/*.test.ts`, `src/data/integrity.test.ts`, all on the memory driver):
- Round trip for every entity: `get` after `put(x)` equals `Contract.parse(x)` (a moment with 3 storylines and 2 cast members included).
- `put` of an invalid row throws the contract's error and writes nothing.
- `listByDays` uses the moment's local day: a moment at `2026-10-24T23:30:00Z` in `Europe/Dublin` is listed on 2026-10-25, not 2026-10-24; deleted moments are excluded by default and included with the flag.
- A second question for the same day → `ConflictError`; `listSince` returns the history in `askedOn` order; `markAnswered` sets the moment id.
- `listOpen` excludes a closed and a deleted storyline; `listDue` respects `next_attempt_at` and the state filter.
- A row written with raw SQL that passes the CHECK constraints but fails its contract (a 600-character note) → `get` throws `CorruptRowError`, and `checkDatabase` reports it as `corruptRow` with table and id.
- With `PRAGMA foreign_keys = OFF` set by the test, a moment pointing at a missing media asset is reported as `foreignKey`.

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; repositories import only contracts, `@life/story` and the driver port.

## T-004d · The encrypted file store · needs T-004c

**Goal.** Originals are stored encrypted with a random key per file, wrapped by a master key held in the keychain; encryption and decryption stream in 1 MiB chunks, detect any tampering, and are tested in Jest with Node adapters that produce the same format as the Expo adapters.

**Do.**
1. `npx expo install expo-crypto expo-secure-store expo-file-system`; add `@noble/hashes` (preamble versions).
2. `src/domain/ports.ts` (types only):
   ```ts
   interface Cipher {
     randomBytes(length: number): Uint8Array;
     seal(key: Uint8Array, nonce: Uint8Array, plaintext: Uint8Array, aad: Uint8Array): Promise<Uint8Array>; // ciphertext ‖ 16-byte tag
     open(key: Uint8Array, nonce: Uint8Array, sealed: Uint8Array, aad: Uint8Array): Promise<Uint8Array>;    // throws on a bad tag
   }
   interface KeyStore { get(name: string): Promise<string | null>; set(name: string, value: string): Promise<void>; remove(name: string): Promise<void> }
   interface FileIO {
     exists(path: string): Promise<boolean>; size(path: string): Promise<number>;
     read(path: string, offset: number, length: number): Promise<Uint8Array>;
     append(path: string, bytes: Uint8Array): Promise<void>; remove(path: string): Promise<void>;
     list(dir: string): Promise<string[]>; ensureDir(dir: string): Promise<void>;
   }
   ```
3. Adapters in `src/services/`: `crypto/expoCipher.ts` (AES-256-GCM with `expo-crypto`; the caller's 12-byte nonce and `additionalData`; returns ciphertext ‖ tag), `secureStore/expoKeyStore.ts` (`expo-secure-store` with `keychainAccessible: AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`, never `requireAuthentication`: the key is needed by background uploads), `files/expoFileIO.ts` (`expo-file-system` `File`, `Directory` and `FileHandle`). Check each API in the installed package's `.d.ts`; name any gap under Risks.
4. `src/data/fileStore/`:
   - `masterKey.ts`: `loadOrCreateMasterKey(keyStore, cipher): Promise<Uint8Array>` — 32 random bytes, base64, under the name `life.masterKey.v1`; a stored value that is not 32 bytes throws `MasterKeyError`.
   - `format.ts`, file format v1: a 28-byte header `"LDE1"` ‖ version `0x01` ‖ 3 zero bytes ‖ chunk size (uint32 BE, 1,048,576) ‖ the asset id's 16 UUID bytes; then chunks `nonce (12) ‖ ciphertext ‖ tag (16)`, each sealing up to 1 MiB of plaintext; the last chunk may be shorter, and an empty file has one empty final chunk. AAD per chunk = asset id bytes ‖ chunk index (uint32 BE) ‖ final flag (1 byte).
   - `fileStore.ts`: `encryptFile({ io, cipher, masterKey, sourcePath, destPath, assetId }): Promise<{ wrappedKey: string; sha256: string; bytes: number }>` — reads the source chunk by chunk (never the whole file), seals, appends, and hashes the plaintext incrementally (`@noble/hashes` sha256); `wrappedKey` = base64(nonce ‖ seal(masterKey, fileKey, aad = `"LDK1"` ‖ asset id bytes)). `decryptFile({ io, cipher, masterKey, sourcePath, destPath, assetId, wrappedKey })` streams back, checking every tag, the chunk order and that the final chunk is present; any failure throws `TamperedFileError` and removes the partial destination.
5. `src/data/fileStore/testing/`: `nodeCipher.ts` (`node:crypto` `aes-256-gcm`), `memoryFileIO.ts`, `memoryKeyStore.ts`.
6. Extend `src/data/integrity.ts` with `checkFiles({ driver, io, keyStore, storeDir }): Promise<IntegrityReport>` adding kinds `missingFile` (an asset whose `localPath` does not exist), `orphanFile` (a file in `storeDir` with no asset row), `missingMasterKey` (assets exist but the key store has no master key).

**Tests** (`src/data/fileStore/*.test.ts`, the integrity test extended):
- Round trip of 0 bytes, exactly 1 MiB, and 3.5 MiB of generated bytes: decrypted bytes equal the source; `sha256` equals `node:crypto`'s; `bytes` is right; the file has `ceil(n / 1 MiB)` chunks (1 for the empty file) and the header fields are right.
- Two encryptions of the same source differ in every chunk (fresh key and nonces).
- `TamperedFileError` for each of: one flipped ciphertext byte, two chunks swapped, the final chunk cut off, a wrong asset id, a wrong master key; the partial destination is removed.
- The source is read in pieces of at most 1 MiB (the memory `FileIO` records read lengths).
- `loadOrCreateMasterKey` creates once and returns the same key after; a 31-byte stored key throws `MasterKeyError`.
- `checkFiles` reports `missingFile`, `orphanFile` and `missingMasterKey`, each in a case built for it, and `ok` on a consistent store.

**Acceptance.** Mobile typecheck, tests, lint, format, boundaries pass; `npx expo-doctor` no new failures; Expo modules imported only under `src/services/`; `data/fileStore` imports only port types, contracts and `@noble/hashes`. Report as UNVERIFIED: the Expo adapters on a device, encryption time and memory for a 50 MB clip, Keychain behaviour across reinstall (these become P-B checks).
